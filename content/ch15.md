## 계층 분리: 응용, 드라이버, HAL

**A등급** HAL(Hardware Abstraction Layer, 하드웨어 추상화 계층)은 레지스터 주소와 CPU 명령을 쓰는 코드를 한 계층에 모아 둔 것입니다. 윗 계층(응용, 드라이버)은 HAL 함수만 부르므로, CPU나 보드가 바뀌어도 HAL만 다시 쓰면 됩니다.

{{svg:figures/ch15_fig01.svg|호출은 위에서 아래로만 향합니다. 하드웨어를 직접 아는 계층은 HAL 하나입니다.}}

| 계층 | 하는 일 | 알아도 되는 것 | 알면 안 되는 것 |
|---|---|---|---|
| 응용 | 제품의 동작 (모드 전환, 화면 구성 등) | 드라이버 함수 | 레지스터 주소, CPU 명령 |
| 드라이버 | 장치 로직 (비트 조작, 상태 머신, 링 버퍼 등) | HAL 함수 | 레지스터 주소, CPU 명령 |
| HAL | 레지스터 접근, 인터럽트 허용 같은 CPU 명령 | 주소, 레지스터 구조, CPU 명령 | 응용의 동작 |

**코드 10-1 · hal.h: 윗 계층이 보는 인터페이스** · 파일: `src/hal/hal.h` · 검증: PC(gcc) 컴파일·실행 통과, 보드 미검증

```c
/* hal.h: 응용과 드라이버가 보는 하드웨어 인터페이스 (주소와 CPU 명령이 나오지 않는다) */
#ifndef HAL_H
#define HAL_H

#include <stdint.h>

void hal_led_write(uint32_t mask);   /* LED 출력 값을 쓴다 (비트 n = LED n) */
void hal_report(void);               /* 시험용: 결과를 출력한다 */

#endif
```

**코드 10-2 · app.c: 응용과 드라이버** · 파일: `src/hal/app.c` · 검증: PC(gcc) 컴파일·실행 통과, 보드 미검증

```c
/* app.c: 응용과 드라이버 (hal.h만 사용한다. 레지스터 주소가 없다) */
#include "hal.h"

static uint32_t led_shadow;          /* 지금까지 출력한 LED 값 */

static void led_set(unsigned n, int on)
{
    if (on) {
        led_shadow |= (1u << n);
    } else {
        led_shadow &= ~(1u << n);
    }
    hal_led_write(led_shadow);       /* 하드웨어 접근은 HAL을 통해서만 한다 */
}

void app_run(void)
{
    led_set(0u, 1);                  /* LED0 켜기 */
    led_set(3u, 1);                  /* LED3 켜기 */
    led_set(0u, 0);                  /* LED0 끄기 */
}
```

`app.c`에는 주소, `REG32`, `volatile`이 없습니다. 이 사실은 빌드 단계에서 `app.c`의 내용을 검사해 확인했습니다. 하드웨어를 건드리는 곳은 `hal_led_write()` 호출 한 줄입니다. 인터페이스는 작게 유지합니다. 함수가 늘수록 CPU마다 다시 써야 할 양이 늘어납니다.

## HAL 구현 바꾸기와 시험용 구현

같은 `hal.h`에 구현을 둘 만들어, 응용 코드는 한 줄도 바꾸지 않고 빌드할 때 어느 쪽을 링크할지만 고릅니다.

**코드 10-3 · hal_regs.c: 레지스터에 쓰는 구현** · 파일: `src/hal/hal_regs.c` · 검증: PC(gcc) 컴파일·실행 통과, 보드 미검증

```c
/* hal_regs.c: 레지스터에 쓰는 HAL 구현 (PC에서는 배열이 레지스터 역할) */
#include <stdint.h>
#include <stdio.h>
#include "hal.h"

/* 보드에서는 이 배열 대신 REG32(주소) 매크로로 실제 주소를 접근한다 */
static volatile uint32_t gpio_led_reg;

void hal_led_write(uint32_t mask)
{
    gpio_led_reg = mask;
}

void hal_report(void)
{
    printf("[10-1] 레지스터 구현: LED 레지스터=0x%02X\n", (unsigned)gpio_led_reg);
}
```

**실행 결과 (PC에서 실제 실행)**

```text
[10-1] 레지스터 구현: LED 레지스터=0x08
```

**코드 10-4 · hal_mock.c: 호출을 기록하는 시험용 구현** · 파일: `src/hal/hal_mock.c` · 검증: PC(gcc) 컴파일·실행 통과, 보드 미검증

```c
/* hal_mock.c: 호출을 기록하는 시험용 HAL 구현 (하드웨어 없이 응용을 시험한다) */
#include <stdint.h>
#include <stdio.h>
#include "hal.h"

#define LOG_MAX  8u

static uint32_t log_val[LOG_MAX];
static unsigned log_n;

void hal_led_write(uint32_t mask)
{
    if (log_n < LOG_MAX) {
        log_val[log_n++] = mask;
    }
}

void hal_report(void)
{
    printf("[10-2] 시험용 구현: hal_led_write 호출=%u회, 값:", log_n);
    for (unsigned i = 0; i < log_n; i++) {
        printf(" 0x%02X", (unsigned)log_val[i]);
    }
    printf("\n");
}
```

**실행 결과 (PC에서 실제 실행)**

```text
[10-2] 시험용 구현: hal_led_write 호출=3회, 값: 0x01 0x09 0x08
```

두 빌드는 `main.c`와 `app.c`가 같고 HAL 파일만 다릅니다(`main.c`는 `app_run()`과 `hal_report()`를 부르는 코드입니다). 시험용 구현은 응용이 LED 값을 `0x01`, `0x09`, `0x08` 순서로 썼다는 것을 하드웨어 없이 확인해 줍니다. 보드에서는 레지스터 구현의 `gpio_led_reg`를 실제 주소 접근(기초 B의 `REG32`)으로 바꿉니다. 이 보드 구현은 이 책에서 실행해 확인하지 않았고(보드 미검증), 이 시리즈의 적용은 부록에 정리합니다.

| 바꾸는 것 | 바뀌는 파일 | 그대로인 파일 |
|---|---|---|
| CPU 교체 | CPU 종속 부분 (인터럽트 허용, CSR 접근) 구현 | 응용, 드라이버, 주변장치 레지스터 접근 코드 |
| 보드 교체 (핀, 주소) | 주소 정의 헤더, 핀 설정 구현 | 응용, 드라이버 |
| PC에서 시험 | 시험용 구현 (호출 기록) | 응용, 드라이버 |

### 작성 규칙

| 규칙 | 이유 |
|---|---|
| 하드웨어 접근은 HAL 함수로만 한다 | 바뀌는 부분이 한곳에 모임 |
| 윗 계층은 아랫 계층만 부른다. 아래에서 위로 알릴 때는 콜백이나 ISR 등록을 쓴다 | 계층이 서로 얽히지 않음 (기초 D) |
| 레지스터 주소는 한 헤더에 모은다 | 보드가 바뀌면 이 헤더만 고침 |
| HAL 인터페이스는 작고 동작 단위로 만든다 ("LED 값을 쓴다") | 구현을 새로 쓸 양이 줄고 의미가 분명함 |
| 드라이버 로직은 시험용 구현으로 PC에서 먼저 시험한다 | 하드웨어 없이도 동작을 확인 |
| CPU에 종속된 코드는 파일 하나로 격리한다 | CPU를 바꿀 때 다시 쓸 범위가 분명함 |

### 자주 겪는 문제

| 증상 | 원인 | 조치 |
|---|---|---|
| 보드를 바꿨더니 여러 파일을 고쳐야 함 | 응용·드라이버 곳곳에 주소와 레지스터 접근이 흩어져 있음 | 접근을 HAL로 옮기고 주소는 한 헤더에 모읍니다. |
| PC에서 시험할 수 없음 | 드라이버가 레지스터를 직접 접근 | HAL 호출로 바꾸고 시험용 구현을 만듭니다. |
| HAL 함수가 계속 늘어남 | 응용의 동작까지 HAL에 넣음 | HAL은 하드웨어 동작 단위만 두고 로직은 드라이버로 올립니다. |
| 호출이 잦은 경로가 느림 | HAL 호출 한 단계가 추가됨 | 헤더에 `static inline`으로 두는 방법이 있습니다. 성능은 측정해 확인합니다. |
| 아래 계층이 위 계층 함수를 직접 부름 | 계층이 거꾸로 의존 | 콜백 등록으로 바꿉니다 (기초 D). |

> **이 시리즈와의 관계** 이 시리즈는 인터럽트 허용·CSR 접근처럼 CPU에 종속된 코드를 파일 하나(`cpu_irq_mbv.c`)에 격리하고, 나머지 주변장치 접근 코드는 CPU와 무관하게 재사용하도록 구성했습니다. 이 장의 계층 분리와 같은 원리입니다.
