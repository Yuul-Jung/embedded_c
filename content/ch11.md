## 초기화 순서: 클록, 핀, 주변장치, 인터럽트

**S등급** 주변장치는 앞 단계가 끝나야 제대로 동작합니다. 순서가 틀려도 컴파일은 되고, 레지스터 쓰기가 조용히 무시되거나 특정 조건에서만 오동작하는 형태로 나타납니다.

{{svg:figures/ch11_fig01.svg|기본 초기화 순서. 앞 단계가 끝난 뒤에 다음 단계로 넘어갑니다.}}

| 단계 | 하는 일 | 앞 단계가 필요한 이유 |
|---|---|---|
| 0 시작 코드 (`main` 이전) | 초기값 있는 전역 변수 복사, 초기값 없는 전역 변수를 0으로 채움 (기법 13) | 이 단계 전에는 전역 변수의 값을 믿을 수 없음 |
| 1 클록 | 시스템 클록 설정, 안정 확인, 주변장치에 클록 공급 | 클록이 공급되지 않는 블록은 레지스터 쓰기를 받지 못할 수 있음 (MCU마다 다름) |
| 2 핀 | 핀 기능 선택, 방향, 출력 초기값 | 주변장치를 켜기 전에 핀이 정해져 있어야 의도하지 않은 값이 밖으로 나가지 않음 |
| 3 주변장치 | 모드·속도 등 설정, 마지막에 enable(켜기) 비트 | 켠 뒤에 설정을 바꾸면 동작 중에 설정이 바뀜 |
| 4 인터럽트 | 장치별 인터럽트 허용, 핸들러 등록, 전역 허용 | 핸들러가 없는 상태에서 요청이 들어오면 처리할 함수가 없음 |

**코드 6-1 · 클록보다 설정을 먼저 한 경우 (가상 UART 모델)** · 파일: `src/test_init.c` · 검증: PC(gcc) 컴파일·실행 통과, 보드 미검증

```c
/* 6-1. 클록이 꺼진 주변장치는 레지스터 쓰기를 받지 못한다 (가상 UART) */
#define SYS_CLK_HZ  100000000u    /* 이 시리즈 SoC의 시스템 클록 */
#define BAUD        115200u

static int      uart_clk_on;      /* 주변장치 클록 공급 여부 */
static uint32_t uart_baud_div;    /* BAUD 분주 레지스터 */

static void clk_enable_uart(void)
{
    uart_clk_on = 1;
}

static void uart_write_baud(uint32_t v)     /* 클록이 꺼져 있으면 쓰기가 무시된다 */
{
    if (uart_clk_on != 0) {
        uart_baud_div = v;
    }
}

static void uart_setup_baud(void)
{
    uart_write_baud(SYS_CLK_HZ / BAUD);
}

static void init_wrong(void)      /* 설정 먼저, 클록 나중 */
{
    uart_setup_baud();
    clk_enable_uart();
}

static void init_right(void)      /* 클록 먼저, 설정 나중 */
{
    clk_enable_uart();
    uart_setup_baud();
}

static void demo_order(void)
{
    uart_clk_on = 0;
    uart_baud_div = 0u;
    init_wrong();
    printf("[6-1] 설정 먼저, 클록 나중: BAUD 분주=%u (쓰기가 무시됨)\n", (unsigned)uart_baud_div);

    uart_clk_on = 0;
    uart_baud_div = 0u;
    init_right();
    printf("      클록 먼저, 설정 나중: BAUD 분주=%u (%u / %u)\n",
           (unsigned)uart_baud_div, (unsigned)SYS_CLK_HZ, (unsigned)BAUD);
}
```

**실행 결과 (PC에서 실제 실행)**

```text
[6-1] 설정 먼저, 클록 나중: BAUD 분주=0 (쓰기가 무시됨)
      클록 먼저, 설정 나중: BAUD 분주=868 (100000000 / 115200)
```

가상 UART는 클록이 꺼져 있으면 쓰기를 무시합니다. 설정을 먼저 하면 분주 레지스터가 0으로 남고, 에러 없이 지나갑니다. 증상은 "UART 출력이 안 나온다"로만 보여서 원인을 찾기 어렵습니다. 실제 보드에서의 동작(쓰기 무시, 버스 오류 등)은 MCU와 장치에 따라 다릅니다.

이 순서는 보드마다 달라지는 부분(클록 트리, 핀 설정 방식)을 제외하면 거의 그대로 유지됩니다. 순서는 `system_init()` 같은 한 함수에 모아 두면 한 곳에서 확인할 수 있습니다.

## 단계별 확인과 핸들러 등록 순서

각 단계는 끝났는지 확인하고, 실패하면 다음 단계로 가지 않습니다. 인터럽트는 핸들러를 등록한 뒤에 허용합니다.

**코드 6-2 · 단계별 확인 (클록 안정 대기에도 제한을 둔다)** · 파일: `src/test_init.c` · 검증: PC(gcc) 컴파일·실행 통과, 보드 미검증

```c
/* 6-2. 단계마다 확인하고, 실패하면 다음 단계로 가지 않는다 */
#define INIT_OK            0
#define INIT_ERR_CLOCK   (-1)

#define STEP_CLOCK  0x1u
#define STEP_PIN    0x2u
#define STEP_UART   0x4u
#define STEP_IRQ    0x8u

static unsigned steps_done;       /* 실행을 마친 단계 */
static uint32_t pll_lock_after;   /* 이 횟수째 확인할 때 클록 잠금 비트가 올라간다 (시험용) */
static uint32_t pll_reads;

static int pll_locked(void)       /* 보드에서는 클록 상태 레지스터의 잠금 비트를 읽는다 */
{
    pll_reads++;
    return pll_reads >= pll_lock_after;
}

static int clock_init(uint32_t max_loops)
{
    while (max_loops-- != 0u) {   /* 클록 안정 대기에도 제한을 둔다 (기법 4) */
        if (pll_locked()) {
            steps_done |= STEP_CLOCK;
            return INIT_OK;
        }
    }
    return INIT_ERR_CLOCK;
}

static void pin_init(void)  { steps_done |= STEP_PIN; }
static void uart_init(void) { steps_done |= STEP_UART; }
static void irq_init(void)  { steps_done |= STEP_IRQ; }

static int system_init(void)
{
    int rc = clock_init(100u);

    if (rc != INIT_OK) {
        return rc;                /* 클록이 없으면 다음 단계로 가지 않는다 */
    }
    pin_init();
    uart_init();
    irq_init();
    return INIT_OK;
}
```

**실행 결과 (PC에서 실제 실행)**

```text
[6-2] 클록이 10번째에 안정: rc=OK, 실행된 단계=클록 핀 UART 인터럽트
      클록이 안정되지 않음: rc=CLOCK, 실행된 단계=없음
```

클록이 안정되지 않으면 이후 단계를 모두 건너뜁니다. 대기에는 기법 4의 제한을 두어, 클록 이상이 부팅 중 무한 대기가 되지 않게 합니다. 실패 코드를 호출한 쪽이 LED 점등이나 UART 메시지로 알리도록 합니다. 클록이 없으면 UART도 쓸 수 없으므로 알리는 방법을 미리 정해 둡니다.

**코드 6-3 · 인터럽트 허용과 핸들러 등록 순서 (가상 시스템)** · 파일: `src/test_init.c` · 검증: PC(gcc) 컴파일·실행 통과, 보드 미검증

```c
/* 6-3. 핸들러가 준비된 뒤에 인터럽트를 허용한다 (가상 시스템) */
typedef void (*handler_t)(void);

static handler_t irq_handler;     /* 등록된 핸들러 (등록 전에는 NULL) */
static int       irq_enabled;     /* 전역 인터럽트 허용 */
static int       irq_pending;     /* 장치가 이미 올려 둔 인터럽트 요청 (부팅 중에 눌린 버튼 등) */
static int       handled;         /* 핸들러가 처리한 횟수 */

static void my_handler(void)
{
    irq_pending = 0;              /* 원인 해제 */
    handled++;
}

static void deliver(void)         /* 허용된 상태에서 요청이 있으면 CPU가 핸들러로 들어간다 */
{
    int guard = 0;

    while (irq_enabled && irq_pending && guard < 3) {   /* guard는 시험용 안전장치 */
        if (irq_handler != NULL) {
            irq_handler();
        }
        guard++;
    }
}

static void irq_enable_all(void)
{
    irq_enabled = 1;
    deliver();
}

static void boot_wrong(void)      /* 허용 먼저, 핸들러 나중 */
{
    irq_enable_all();
    irq_handler = my_handler;
}

static void boot_right(void)      /* 핸들러 먼저, 허용 나중 */
{
    irq_handler = my_handler;
    irq_enable_all();
}

static void boot_reset(void)
{
    irq_handler = NULL;
    irq_enabled = 0;
    irq_pending = 1;
    handled = 0;
}

static void demo_irq_order(void)
{
    boot_reset();
    boot_wrong();
    printf("[6-3] 인터럽트를 먼저 허용: 처리=%d회, 요청 남음=%d\n", handled, irq_pending);

    boot_reset();
    boot_right();
    printf("      핸들러를 먼저 등록: 처리=%d회, 요청 남음=%d\n", handled, irq_pending);
}
```

**실행 결과 (PC에서 실제 실행)**

```text
[6-3] 인터럽트를 먼저 허용: 처리=0회, 요청 남음=1
      핸들러를 먼저 등록: 처리=1회, 요청 남음=0
```

부팅 중에 이미 올라온 요청(눌러 둔 버튼 등)은 인터럽트를 허용하는 순간 처리 대상이 됩니다. 핸들러가 없으면 처리되지 않은 요청이 남습니다. 실제 CPU의 동작은 구현에 따라 다르며(비어 있는 함수 호출, 같은 요청으로 반복 진입 등) 어느 쪽이든 오동작입니다. 핸들러 등록은 기초 D, 원인 해제는 기법 5를 참고합니다.

### 작성 규칙

| 규칙 | 이유 |
|---|---|
| 순서는 클록, 핀, 주변장치, 인터럽트 | 앞 단계가 끝나야 다음 단계가 의미를 가짐 |
| 주변장치는 설정을 마친 뒤 마지막에 켠다 | 켜진 상태에서 설정이 바뀌지 않음 |
| 핸들러를 등록한 뒤에 인터럽트를 허용한다 | 허용하는 순간 대기 중인 요청이 처리 대상이 됨 |
| 초기화 순서는 한 함수에 모은다 | 순서를 한 곳에서 확인하고 바꿀 수 있음 |
| 클록 안정 대기 등 기다리는 곳에 제한을 둔다 (기법 4) | 하드웨어 이상이 부팅 중 무한 대기가 되지 않음 |
| 단계가 실패하면 다음 단계로 가지 않고 실패 코드를 돌려준다 | 미완성 상태에서 나머지 주변장치를 건드리지 않음 |

### 자주 겪는 문제

| 증상 | 원인 | 조치 |
|---|---|---|
| 레지스터를 썼는데 값이 바뀌지 않음 | 해당 블록의 클록이 아직 공급되지 않음 | 클록 공급을 설정보다 먼저 합니다(코드 6-1). |
| 전원을 켠 직후 핀에서 짧게 잘못된 값이 나감 | 핀 방향·초기값을 정하기 전에 주변장치를 켬 | 핀을 먼저 정하고 주변장치를 켭니다. |
| 부팅 직후 한 번 동작이 이상하고 다시 하면 정상 | 인터럽트를 먼저 허용해 초기화 중에 핸들러가 실행됨 | 핸들러와 필요한 변수를 준비한 뒤 허용합니다(코드 6-3). |
| 부팅 도중 멈춘 것처럼 보임 | 클록 안정 같은 대기에 제한이 없음 | 제한을 두고 실패 코드를 돌려줍니다(코드 6-2). |
| 전역 변수 초기값이 가끔 틀림 | 시작 코드 단계(변수 복사·0 채움)가 실행되기 전에 변수를 사용 | 기법 13 |

> **CPU 종속 부분** 클록·핀·인터럽트 허용의 구체적인 레지스터와 방법은 CPU와 보드마다 다릅니다. 이 장의 순서는 공통이고, 레지스터 접근 코드만 CPU 종속 파일에 둡니다(기법 10). 이 시리즈의 각 실습에서의 적용은 부록에 정리합니다.
