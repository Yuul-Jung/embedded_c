## 포인터는 주소를 담은 변수

포인터 변수에는 값이 아니라 주소가 들어 있습니다. 포인터의 형은 그 주소에서 몇 바이트를 어떻게 읽을지를 정합니다.

| 표기 | 뜻 | 예 |
|---|---|---|
| `&x` | 변수 `x`의 주소 | `p = &x;` |
| `*p` | 주소 `p`에 있는 값 (역참조, Dereference) | `*p = 7;` |
| `p + n` | 주소를 **n × sizeof(\*p)** 바이트만큼 이동 | `uint32_t *`에 1을 더하면 4바이트 |
| `p[n]` | `*(p + n)`과 같은 표기 | `arr[2]` = `*(arr + 2)` |

{{svg:figures/ch03_fig01.svg|같은 1을 더해도 포인터의 형에 따라 이동 거리가 다릅니다. 4바이트 형은 4바이트, 1바이트 형은 1바이트 이동합니다.}}

**코드 B-1 · 포인터 산술** · 파일: `src/test_basic.c` · 검증: PC(gcc) 컴파일·실행 통과, 보드 미검증

```c
/* B-1. 포인터 산술: 더하는 값은 "바이트"가 아니라 "원소 개수" */
static void demo_ptr_arith(void)
{
    uint32_t arr[4] = {10, 20, 30, 40};
    uint32_t *p32 = &arr[0];
    uint8_t  *p8  = (uint8_t *)&arr[0];

    printf("[B-1] (p32+1) - p32 주소 차이 = %zu 바이트, *(p32+1) = %u\n",
           (size_t)((uintptr_t)(p32 + 1) - (uintptr_t)p32), (unsigned)*(p32 + 1));
    printf("      (p8 +1) - p8  주소 차이 = %zu 바이트\n",
           (size_t)((uintptr_t)(p8 + 1) - (uintptr_t)p8));
    printf("      arr[2] == *(arr+2) ? %s\n", (arr[2] == *(arr + 2)) ? "참" : "거짓");
}
```

**실행 결과 (PC에서 실제 실행)**

```text
[B-1] (p32+1) - p32 주소 차이 = 4 바이트, *(p32+1) = 20
      (p8 +1) - p8  주소 차이 = 1 바이트
      arr[2] == *(arr+2) ? 참
```

**코드 B-4 · 값 전달과 포인터 전달** · 파일: `src/test_basic.c` · 검증: PC(gcc) 컴파일·실행 통과, 보드 미검증

```c
/* B-4. 포인터를 인자로 넘겨 호출자의 값을 바꾸기 */
static void inc_by_ptr(uint32_t *x) { *x += 1; }
static void inc_by_val(uint32_t x)  { x += 1; (void)x; }

static void demo_pass(void)
{
    uint32_t a = 5, b = 5;
    inc_by_val(a);
    inc_by_ptr(&b);
    printf("[B-4] 값 전달 후 a=%u, 포인터 전달 후 b=%u\n", (unsigned)a, (unsigned)b);
}
```

**실행 결과 (PC에서 실제 실행)**

```text
[B-4] 값 전달 후 a=5, 포인터 전달 후 b=6
```

함수에 값을 넘기면 복사본만 바뀌고, 주소를 넘기면 호출한 쪽의 변수가 바뀝니다. 레지스터와 버퍼를 다루는 드라이버 함수는 거의 모두 이 형태입니다.

> **함정** `uint32_t *p`에서 `p + 4`는 4바이트가 아니라 16바이트를 이동합니다. 데이터시트의 레지스터 오프셋은 바이트 단위이므로, 오프셋 계산에 포인터 산술을 섞으면 어긋납니다. 다음 페이지의 방식으로 주소를 정수로 계산합니다.

## 정수를 주소로 읽고 쓰기

`REG32(addr)`는 레지스터 접근의 원형입니다. 주소를 정수로 계산하고, 접근하는 순간에만 포인터로 바꿔 읽고 씁니다.

**코드 B-2 · 가짜 레지스터 블록과 REG32 매크로** · 파일: `src/test_basic.c` · 검증: PC(gcc) 컴파일·실행 통과, 보드 미검증

```c
/* B-2. 정수를 주소로 해석해 읽고 쓰기 (레지스터 접근의 원형)
 * 실제 보드에서는 0x40000000 같은 고정 주소를 쓰지만,
 * PC에서는 그 주소가 유효하지 않으므로 배열을 "가짜 레지스터 블록"으로 쓴다. */
static uint32_t fake_regs[4];                 /* 0:DATA 1:TRI 2:CTRL 3:STATUS */

#define REG32(addr)  (*(volatile uint32_t *)(uintptr_t)(addr))

static void demo_reg_access(void)
{
    uintptr_t base = (uintptr_t)fake_regs;    /* 보드에서는 base = 0x40000000 */

    REG32(base + 0x0) = 0xA5u;                /* DATA 레지스터에 쓰기 */
    REG32(base + 0x4) = 0x00u;                /* TRI  레지스터에 쓰기 */
    REG32(base + 0x8) |= (1u << 3);           /* 읽기-수정-쓰기: 비트 3만 켬 */

    printf("[B-2] fake_regs[0]=0x%02X fake_regs[1]=0x%02X fake_regs[2]=0x%02X\n",
           (unsigned)fake_regs[0], (unsigned)fake_regs[1], (unsigned)fake_regs[2]);
    printf("      REG32(base+0x0) 읽기 = 0x%02X\n", (unsigned)REG32(base + 0x0));
}
```

**실행 결과 (PC에서 실제 실행)**

```text
[B-2] fake_regs[0]=0xA5 fake_regs[1]=0x00 fake_regs[2]=0x08
      REG32(base+0x0) 읽기 = 0xA5
```

| 조각 | 역할 |
|---|---|
| `(uintptr_t)(addr)` | 주소를 담을 수 있는 정수형으로 계산합니다. 오프셋은 바이트 단위로 더합니다. |
| `(volatile uint32_t *)` | 그 정수를 32비트 접근용 포인터로 해석합니다. `volatile`의 이유는 기법 2에서 다룹니다. |
| 바깥쪽 `*` | 역참조입니다. 대입의 왼쪽에 쓰면 쓰기, 오른쪽에 쓰면 읽기가 됩니다. |

> **보드로 옮길 때** PC에서는 배열을 가짜 레지스터로 쓰고, 보드에서는 기준 주소만 바뀝니다. 예를 들어 `GPIO_LEDSW_BASE`를 `0x40000000`으로 두고 `REG32(GPIO_LEDSW_BASE + 0x0)`에 씁니다.

### 형 변환과 const

**코드 B-3 · 같은 메모리를 다른 폭으로 보기** · 파일: `src/test_basic.c` · 검증: PC(gcc) 컴파일·실행 통과, 보드 미검증

```c
/* B-3. 형 변환으로 같은 메모리를 다른 폭으로 보기 */
static void demo_cast_view(void)
{
    uint32_t v = 0xAABBCCDDu;
    uint16_t lo, hi;
    memcpy(&lo, (const uint8_t *)&v + 0, sizeof lo);
    memcpy(&hi, (const uint8_t *)&v + 2, sizeof hi);
    printf("[B-3] v=0x%08X 하위16=0x%04X 상위16=0x%04X (little-endian)\n",
           (unsigned)v, (unsigned)lo, (unsigned)hi);
}
```

**실행 결과 (PC에서 실제 실행)**

```text
[B-3] v=0xAABBCCDD 하위16=0xCCDD 상위16=0xAABB (little-endian)
```

**코드 B-5 · const의 위치** · 파일: `src/test_basic.c` · 검증: PC(gcc) 컴파일·실행 통과, 보드 미검증

```c
/* B-5. const 위치에 따른 의미 */
static void demo_const(void)
{
    uint32_t x = 1, y = 2;
    const uint32_t *p1 = &x;        /* 가리키는 값 수정 불가, 포인터 변경 가능 */
    uint32_t *const p2 = &x;        /* 가리키는 값 수정 가능, 포인터 변경 불가 */
    p1 = &y;                        /* 가능 */
    *p2 = 7;                        /* 가능 */
    printf("[B-5] *p1=%u (y를 가리킴), x=%u (p2로 수정됨)\n", (unsigned)*p1, (unsigned)x);
}
```

**실행 결과 (PC에서 실제 실행)**

```text
[B-5] *p1=2 (y를 가리킴), x=7 (p2로 수정됨)
```

| 선언 | 읽는 법 | 바꿀 수 있는 것 |
|---|---|---|
| `const uint32_t *p` | p는 "const인 uint32\_t"를 가리킨다 | `p` 자체는 가능, `*p`는 불가 |
| `uint32_t *const p` | p는 "uint32\_t를 가리키는 const 포인터"다 | `*p`는 가능, `p` 자체는 불가 |

### 자주 겪는 문제

| 증상 | 원인 | 조치 |
|---|---|---|
| 정수 주소를 바로 역참조하면 컴파일 오류 | 정수에서 포인터로의 형 변환이 빠짐 | `REG32` 매크로를 사용합니다. |
| PC에서 `0x40000000`에 접근하면 프로그램이 즉시 종료 | PC 프로세스에는 그 주소가 매핑되어 있지 않음 | 배열을 가짜 레지스터로 두고 테스트합니다. |
| 홀수 주소를 `uint32_t *`로 읽으면 이상 동작 | 정렬 위반(비정렬 접근, Unaligned Access). 구현에 따라 예외가 나거나 느려짐 | `memcpy`나 바이트 단위 조합으로 읽습니다(코드 B-3 방식). |
