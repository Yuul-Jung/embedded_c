## 링 버퍼: 쓰는 쪽과 읽는 쪽의 인덱스

**A등급** 링 버퍼(Ring Buffer, 원형 큐)는 고정 크기 배열을 돌려 쓰는 대기열입니다. 먼저 들어온 값이 먼저 나오고(FIFO), 메모리를 동적으로 잡지 않으며, 쓰는 쪽과 읽는 쪽이 서로 다른 인덱스만 고치므로 ISR(기법 5)과 메인 사이의 데이터 전달에 알맞습니다.

{{svg:figures/ch12_fig01.svg|크기 8, head = 10, tail = 6. 인덱스는 계속 늘어나고 배열 위치는 `인덱스 & 7`로 구합니다.}}

| 항목 | 내용 |
|---|---|
| `head` | 지금까지 쓴 개수. 쓰는 쪽만 고칩니다. |
| `tail` | 지금까지 읽은 개수. 읽는 쪽만 고칩니다. |
| 들어 있는 개수 | `head - tail` (부호 없는 뺄셈이라 인덱스가 되감겨도 맞음, 기법 3) |
| 비어 있음 / 가득 참 | 개수 == 0 / 개수 == 크기 |
| 배열 위치 | `인덱스 & (크기 - 1)`. 크기가 2의 거듭제곱일 때만 성립 (나눗셈 없이 구함) |

**코드 7-1 · 링 버퍼의 구현** · 파일: `src/test_ring.c` · 검증: PC(gcc) 컴파일·실행 통과, 보드 미검증

```c
/* 7-1. 링 버퍼: 쓰는 쪽(head)과 읽는 쪽(tail)이 각자 자기 인덱스만 고친다 */
#define RING_SIZE  8u                         /* 2의 거듭제곱 */
#define RING_MASK  (RING_SIZE - 1u)

typedef struct {
    uint8_t           data[RING_SIZE];
    volatile uint32_t head;                   /* 쓴 개수 (쓰는 쪽만 고친다) */
    volatile uint32_t tail;                   /* 읽은 개수 (읽는 쪽만 고친다) */
} ring_t;

_Static_assert((RING_SIZE & (RING_SIZE - 1u)) == 0u, "RING_SIZE는 2의 거듭제곱이어야 한다");

static uint32_t ring_count(const ring_t *r)   /* 들어 있는 개수. 부호 없는 뺄셈이라 되감겨도 맞다 */
{
    return r->head - r->tail;
}

static bool ring_push(ring_t *r, uint8_t v)   /* 쓰는 쪽에서 호출 */
{
    if (ring_count(r) >= RING_SIZE) {
        return false;                         /* 가득 참: 새 값을 버린다 */
    }
    r->data[r->head & RING_MASK] = v;         /* 값을 먼저 쓰고 */
    r->head = r->head + 1u;                   /* 인덱스를 나중에 올린다 */
    return true;
}

static bool ring_pop(ring_t *r, uint8_t *v)   /* 읽는 쪽에서 호출 */
{
    if (ring_count(r) == 0u) {
        return false;                         /* 비어 있음 */
    }
    *v = r->data[r->tail & RING_MASK];        /* 값을 먼저 읽고 */
    r->tail = r->tail + 1u;                   /* 인덱스를 나중에 올린다 */
    return true;
}

static void demo_ring(void)
{
    ring_t r = { {0}, 0u, 0u };
    uint8_t v;
    int ok = 0;

    for (uint8_t i = 0; i < 10u; i++) {       /* 크기 8인 버퍼에 10개를 넣는다 */
        if (ring_push(&r, (uint8_t)(0x40u + i))) {
            ok++;
        }
    }
    printf("[7-1] 10개를 넣음: 들어간 개수=%d, 버퍼 안=%u개\n", ok, (unsigned)ring_count(&r));
    printf("      꺼낸 순서:");
    while (ring_pop(&r, &v)) {
        printf(" %02X", (unsigned)v);
    }
    printf("\n");

    r.head = 0xFFFFFFFCu;                     /* 인덱스가 되감기기 직전에서 시작 */
    r.tail = 0xFFFFFFFCu;
    for (uint8_t i = 0; i < 6u; i++) {
        (void)ring_push(&r, (uint8_t)(0x50u + i));
    }
    printf("      인덱스 되감김: head=0x%08X, tail=0x%08X, 개수=%u\n",
           (unsigned)r.head, (unsigned)r.tail, (unsigned)ring_count(&r));
    printf("      꺼낸 순서:");
    while (ring_pop(&r, &v)) {
        printf(" %02X", (unsigned)v);
    }
    printf("\n");
}
```

**실행 결과 (PC에서 실제 실행)**

```text
[7-1] 10개를 넣음: 들어간 개수=8, 버퍼 안=8개
      꺼낸 순서: 40 41 42 43 44 45 46 47
      인덱스 되감김: head=0x00000002, tail=0xFFFFFFFC, 개수=6
      꺼낸 순서: 50 51 52 53 54 55
```

크기 8인 버퍼에 10개를 넣으면 8개만 들어가고 나머지 2개는 버려집니다. 인덱스를 0으로 되돌리지 않고 계속 늘리므로 가득 참과 비어 있음을 인덱스만으로 구별할 수 있고, 한 칸을 비워 둘 필요가 없습니다. 인덱스가 `0xFFFFFFFF`를 넘어 되감겨도 개수 계산과 위치 계산이 맞습니다.

## ISR과 메인 사이의 데이터 전달

ISR이 `push`, 메인이 `pop`을 맡으면 두 쪽이 같은 변수를 동시에 고치는 일이 없습니다. 가득 찼을 때의 동작은 미리 정해 두고, 버린 개수는 세어 둡니다.

**코드 7-2 · 수신 ISR과 메인** · 파일: `src/test_ring.c` · 검증: PC(gcc) 컴파일·실행 통과, 보드 미검증

```c
/* 7-2. 수신 ISR이 넣고 메인이 꺼낸다. 가득 차서 버린 개수를 센다 */
static ring_t   rx;
static volatile uint32_t rx_dropped;          /* ISR만 고친다 */

static void rx_isr(uint8_t byte)              /* 바이트가 도착하면 호출되는 함수 */
{
    if (!ring_push(&rx, byte)) {
        rx_dropped++;
    }
}

static unsigned drain(void)                   /* 메인에서 쌓인 바이트를 모두 처리 */
{
    uint8_t v;
    unsigned n = 0;

    while (ring_pop(&rx, &v)) {
        n++;
    }
    return n;
}

static void demo_rx(void)
{
    unsigned got = 0;

    for (uint8_t i = 0; i < 6u; i++) {        /* 메인이 바쁜 사이 6바이트 도착 */
        rx_isr(i);
    }
    got += drain();
    for (uint8_t i = 0; i < 12u; i++) {       /* 메인이 더 오래 바쁜 사이 12바이트 도착 */
        rx_isr(i);
    }
    got += drain();
    printf("[7-2] 총 18바이트 도착, 크기 %u: 처리=%u, 버림=%u\n",
           (unsigned)RING_SIZE, got, (unsigned)rx_dropped);
}
```

**실행 결과 (PC에서 실제 실행)**

```text
[7-2] 총 18바이트 도착, 크기 8: 처리=14, 버림=4
```

메인이 바쁜 사이 6바이트가 도착했을 때는 모두 보관됩니다. 12바이트가 한꺼번에 도착했을 때는 크기 8을 넘는 4바이트가 버려지고, 버린 개수를 `rx_dropped`로 확인할 수 있습니다. 크기는 "도착 속도 × 메인이 바쁠 수 있는 최대 시간"으로 정합니다. UART 115200 bps 8N1은 1바이트가 약 86.8 µs이므로(기법 4), 메인이 10 ms 동안 바쁘면 약 115바이트가 쌓입니다.

| 가득 찼을 때 | 방식 | 쓰임 |
|---|---|---|
| 새 값을 버림 | `push`가 `false`를 반환 (코드 7-1) | 오래된 값이 중요한 통신 수신 |
| 오래된 값을 덮어씀 | 쓰는 쪽이 `tail`까지 고치게 되어 읽는 쪽과 경합함. 이 구현으로는 안전하지 않음 | 최신 값만 필요한 센서 값 (별도 설계 필요) |

### 작성 규칙

| 규칙 | 이유 |
|---|---|
| 쓰는 쪽은 `head`만, 읽는 쪽은 `tail`만 고친다 | 두 쪽이 같은 변수를 고치지 않으므로 경합이 없음 |
| `head`, `tail`은 `volatile` | 다른 쪽이 고치는 값을 매번 읽음 (기법 2, 5) |
| 값을 먼저 쓰고, 인덱스를 나중에 올린다 | 읽는 쪽이 아직 쓰지 않은 칸을 읽지 않음 |
| 크기는 2의 거듭제곱으로 하고 `_Static_assert`로 확인 | `&` 연산으로 위치를 구할 수 있음 |
| 가득 찼을 때의 동작을 정하고 버린 개수를 센다 | 데이터 손실을 알아차릴 수 있음 |
| 쓰는 쪽 하나, 읽는 쪽 하나로 제한한다 | 쓰는 쪽이 둘이면 `head`를 서로 고치게 됨 (기법 11) |

### 자주 겪는 문제

| 증상 | 원인 | 조치 |
|---|---|---|
| 수신 데이터가 가끔 빠짐 | 버퍼가 가득 차 새 값을 버림 | 버린 개수를 확인하고 크기를 늘리거나 메인의 처리 주기를 줄입니다. |
| 가득 참과 비어 있음이 헷갈림 | 인덱스를 0으로 되돌리는 방식에서 두 상태의 인덱스가 같아짐 | 인덱스를 계속 늘리고 `head - tail`로 개수를 구합니다. |
| 크기를 6, 10처럼 정했더니 데이터가 섞임 | `&` 연산은 2의 거듭제곱 크기에서만 맞음 | 크기를 2의 거듭제곱으로 하고 `_Static_assert`를 둡니다. |
| 최적화한 빌드에서만 메인이 데이터를 못 봄 | `head`에 `volatile`이 빠짐 | 인덱스에 `volatile`을 붙입니다. |
| 쓰는 쪽이 둘인데 값이 깨짐 | 두 곳이 `head`를 동시에 고침 | 쓰는 쪽을 하나로 하거나 임계 구역으로 보호합니다(기법 11). |

> **미검증** 이 구현은 단일 코어에서 ISR 하나가 쓰고 메인이 읽는 구조를 가정합니다. 인덱스를 올리기 전에 배열 쓰기가 끝났다는 보장(컴파일러 배리어, 멀티코어의 메모리 배리어)은 이 장에서 다루지 않았고 PC 실행으로도 확인할 수 없습니다. 쓰이는 CPU의 규칙으로 확인합니다.
