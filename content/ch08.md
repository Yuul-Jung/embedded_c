## int의 크기는 정해져 있지 않다

**S등급** `int`, `long`, `char`의 크기와 부호는 컴파일러와 대상 CPU가 정합니다. 레지스터는 비트 폭이 정해진 하드웨어이므로 코드도 폭이 정해진 형으로 씁니다.

### 대상별 형의 크기 (바이트)

| 대상 | char의 부호 | short | int | long | long long | 포인터 | uint32\_t의 기본형 |
|---|---|---|---|---|---|---|---|
| PC (x86-64) | 부호 있음 | 2 | 4 | 8 | 8 | 8 | `unsigned int` |
| ARM Cortex-M (thumbv7m) | 부호 없음 | 2 | 4 | 4 | 8 | 4 | `unsigned int` |
| RISC-V 32비트 (riscv32) | 부호 없음 | 2 | 4 | 4 | 8 | 4 | `unsigned int` |
| RISC-V 64비트 (riscv64) | 부호 없음 | 2 | 4 | 8 | 8 | 8 | `unsigned int` |
| AVR (avr) | 부호 있음 | 2 | 2 | 4 | 8 | 2 | `unsigned long` |
| MSP430 (msp430) | 부호 있음 | 2 | 2 | 4 | 8 | 2 | `unsigned long` |

같은 `long`이 PC에서는 8바이트, 32비트 RISC-V에서는 4바이트입니다. 16비트 AVR과 MSP430에서는 `int`가 2바이트입니다. `char`의 부호도 PC(x86-64)는 있음, RISC-V와 ARM은 없음으로 다릅니다.

### stdint.h의 형

**clang 18.1.3의 대상별 내장 매크로(__SIZEOF_INT__ 등) 값**

| 형 | 의미 | 용도 |
|---|---|---|
| `uint8_t` `uint16_t` `uint32_t` `uint64_t` | 정확히 그 비트 폭의 부호 없는 정수 | 레지스터, 비트 연산, 바이트 데이터, 통신 필드 |
| `int8_t` ~ `int64_t` | 정확히 그 비트 폭의 부호 있는 정수 | 음수가 의미 있는 값(센서 측정값 등) |
| `uintptr_t` | 포인터를 담을 수 있는 정수 | 주소 계산, `REG32` |
| `size_t` | `sizeof`의 결과 형 | 크기, 개수, 배열 첨자 |
| `uint_fast8_t` 등 | 최소 그 폭 이상인 가장 빠른 형 | 폭이 대상마다 달라서 레지스터·구조체에는 쓰지 않음 |

**코드 3-1 · 형의 크기와 char의 부호** · 파일: `src/test_int.c` · 검증: PC(gcc) 컴파일·실행 통과, 보드 미검증

```c
/* 3-1. 형의 크기와 char의 부호 */
int char_to_int(void)
{
    char c = (char)200;          /* char가 부호 있는 형인지에 따라 값이 달라진다 */
    return c;
}

static void demo_sizes(void)
{
    printf("[3-1] char=%zu short=%zu int=%zu long=%zu long long=%zu 포인터=%zu\n",
           sizeof(char), sizeof(short), sizeof(int), sizeof(long),
           sizeof(long long), sizeof(void *));
    printf("      uint8_t=%zu uint16_t=%zu uint32_t=%zu uint64_t=%zu\n",
           sizeof(uint8_t), sizeof(uint16_t), sizeof(uint32_t), sizeof(uint64_t));
    printf("      CHAR_MIN=%d (char는 부호 %s), char_to_int()=%d\n",
           CHAR_MIN, (CHAR_MIN < 0) ? "있음" : "없음", char_to_int());
}
```

**실행 결과 (PC에서 실제 실행)**

```text
[3-1] char=1 short=2 int=4 long=8 long long=8 포인터=8
      uint8_t=1 uint16_t=2 uint32_t=4 uint64_t=8
      CHAR_MIN=-128 (char는 부호 있음), char_to_int()=-56
```

**컴파일 결과 · RISC-V rv32imc, clang 18.1.3, -O2**

```asm
char_to_int:
    li    a0, 200
    ret
```

같은 `char_to_int()`가 PC에서는 -56을, RISC-V용으로 컴파일하면 200(`li a0, 200`)을 돌려줍니다. PC에서 통과한 문자·바이트 코드가 보드에서 다르게 동작할 수 있는 이유입니다.

**코드 3-2 · 크기는 컴파일 단계에서 확인하고, 출력은 PRI 매크로로** · 파일: `src/test_int.c` · 검증: PC(gcc) 컴파일·실행 통과, 보드 미검증

```c
/* 3-2. 크기는 컴파일 단계에서 확인하고, 출력은 PRI 매크로로 */
_Static_assert(sizeof(uint32_t) == 4, "uint32_t는 4바이트여야 한다");
_Static_assert(sizeof(uintptr_t) >= sizeof(void *), "uintptr_t는 포인터를 담아야 한다");

static void demo_fmt(void)
{
    uint32_t x = 4000000000u;
    uint8_t  b = 0xA5u;

    printf("[3-2] x=%" PRIu32 " (0x%08" PRIX32 "), b=0x%02" PRIX8 "\n", x, x, b);
}
```

**실행 결과 (PC에서 실제 실행)**

```text
[3-2] x=4000000000 (0xEE6B2800), b=0xA5
```

`_Static_assert`로 가정한 크기가 맞는지 빌드 단계에서 확인합니다. `uint32_t`의 기본형이 대상마다 달라서(위 표의 마지막 열: AVR은 `unsigned long`, 32비트 대상은 `unsigned int`) `%u`나 `%lu`를 직접 쓰면 경고가 나거나 값이 깨집니다. `PRIu32`, `PRIX32`처럼 형에 맞는 매크로를 씁니다.

> **참고** 고정 폭 정수형(`intN_t`)은 해당 폭의 형이 있는 대상에서만 정의됩니다. 일반적인 32비트 MCU에서는 8, 16, 32, 64비트형이 제공됩니다.

## 부호, 승격, 되감김

고정 폭 형을 써도 부호와 승격 규칙을 모르면 값이 어긋납니다. 레지스터와 비트 연산에는 부호 없는 형을 씁니다.

**코드 3-3 · 정수 승격과 잘림** · 파일: `src/test_int.c` · 검증: PC(gcc) 컴파일·실행 통과, 보드 미검증

```c
/* 3-3. 정수 승격과 잘림 */
static void demo_promote(void)
{
    uint8_t a = 200u, b = 100u;
    uint8_t c = (uint8_t)(a + b);     /* a + b는 int로 계산되어 300, 대입하면서 하위 8비트만 남아 44 */
    int     d = a + b;                /* int 그대로 300 */

    printf("[3-3] c=%u d=%d, (a + b > 255) = %d\n", (unsigned)c, d, (a + b) > 255);
}
```

**실행 결과 (PC에서 실제 실행)**

```text
[3-3] c=44 d=300, (a + b > 255) = 1
```

`uint8_t` 둘을 더하면 `int`로 승격되어 계산되므로 300이 되고, `uint8_t`에 담을 때 하위 8비트만 남아 44가 됩니다.

**코드 3-4 · 부호 있는 값과 부호 없는 값의 비교** · 파일: `src/test_int.c` · 검증: PC(gcc) 컴파일·실행 통과, 보드 미검증

```c
/* 3-4. 부호 있는 값과 부호 없는 값의 비교 */
#pragma GCC diagnostic push
#pragma GCC diagnostic ignored "-Wsign-compare"   /* 문제를 보이려고 경고를 일부러 끈다 */
static int less_mixed(int i, unsigned u)
{
    return i < u;                     /* i가 unsigned로 변환되어 비교된다 */
}
#pragma GCC diagnostic pop

static void demo_mixed(void)
{
    printf("[3-4] -1 < 1u ? %s, (unsigned)-1 = %u\n",
           less_mixed(-1, 1u) ? "참" : "거짓", (unsigned)-1);
}
```

**실행 결과 (PC에서 실제 실행)**

```text
[3-4] -1 < 1u ? 거짓, (unsigned)-1 = 4294967295
```

부호 있는 값과 부호 없는 값을 비교하면 부호 있는 쪽이 `unsigned`로 바뀝니다. -1이 4294967295가 되어 `-1 < 1u`가 거짓이 됩니다. 컴파일러의 `-Wsign-compare` 경고는 이 문제를 알려 주므로 무시하지 않습니다.

**코드 3-5 · 틱 카운터가 되감길 때의 시간 비교** · 파일: `src/test_int.c` · 검증: PC(gcc) 컴파일·실행 통과, 보드 미검증

```c
/* 3-5. 틱 카운터가 되감길 때의 시간 비교 */
static uint32_t ticks_now;            /* 1 ms마다 1씩 늘어나는 가상 틱 */

static int timed_out_wrong(uint32_t start, uint32_t timeout)
{
    return ticks_now > start + timeout;                 /* 되감기면 틀린다 */
}

static int timed_out_right(uint32_t start, uint32_t timeout)
{
    return (uint32_t)(ticks_now - start) >= timeout;    /* 뺄셈은 되감김과 무관하다 */
}

static void demo_wrap(void)
{
    uint32_t start   = 0xFFFFFFF0u;   /* 되감기기 16틱 전에 시작 */
    uint32_t timeout = 0x20u;         /* 32틱 */
    static const uint32_t now_list[2] = { 0xFFFFFFF8u, 0x00000010u };   /* 8틱 경과, 32틱 경과 */

    printf("[3-5] start=0x%08" PRIX32 " timeout=%" PRIu32 "\n", start, timeout);
    for (int i = 0; i < 2; i++) {
        ticks_now = now_list[i];
        printf("      now=0x%08" PRIX32 " 경과=%2" PRIu32 "틱  틀린 식=%d  맞는 식=%d\n",
               ticks_now, (uint32_t)(ticks_now - start),
               timed_out_wrong(start, timeout), timed_out_right(start, timeout));
    }
}
```

**실행 결과 (PC에서 실제 실행)**

```text
[3-5] start=0xFFFFFFF0 timeout=32
      now=0xFFFFFFF8 경과= 8틱  틀린 식=1  맞는 식=0
      now=0x00000010 경과=32틱  틀린 식=0  맞는 식=1
```

1 ms 틱을 쓰는 32비트 카운터는 약 49.7일마다 되감깁니다. `start + timeout`을 먼저 계산해 비교하는 식은 되감김 근처에서 틀리고, 뺄셈으로 경과를 구하는 식은 항상 맞습니다. 이 방식은 기법 9에서 다시 씁니다.

### 작성 규칙

| 규칙 | 이유 |
|---|---|
| 레지스터 접근과 비트 연산은 부호 없는 고정 폭 형 | 부호 있는 형의 시프트와 오버플로는 정의되지 않음(기법 1) |
| 상수에 `u` 접미사 (`1u`, `0x80u`) | 부호 있는 `int`로 계산되는 것을 막음 |
| 바이트 데이터는 `uint8_t`, 문자열은 `char` | `char`의 부호가 대상마다 다름 |
| 시간 제한은 뺄셈으로 비교 | 카운터가 되감겨도 맞음 |
| 출력은 `PRIu32` 등 매크로 | `uint32_t`의 기본형이 대상마다 다름 |
| 구조체·통신 필드에 `int`, `long` 금지 | 크기와 패딩이 대상마다 달라짐(기초 C) |

### 자주 겪는 문제

| 증상 | 원인 | 조치 |
|---|---|---|
| PC에서 되던 코드가 보드에서 다른 값을 냄 | `int`, `long`, `char`의 크기·부호 가정 | 고정 폭 형을 쓰고 `_Static_assert`로 크기를 확인합니다. |
| 바이트 값 비교 결과가 PC와 보드에서 다름 | plain `char`의 부호가 다름 | 바이트 값은 `uint8_t`를 씁니다. |
| `printf` 출력이 깨지거나 컴파일 경고 | `%u`, `%lu`를 `uint32_t`에 직접 사용 | `PRIu32` 등을 씁니다. |
| 8비트 변수 계산 결과가 예상과 다름 | `int`로 승격된 뒤 잘림 | 결과를 담는 형과 캐스트를 명시합니다. |
| 음수 비교가 거꾸로 나옴 | 부호 있는 값과 없는 값을 섞음 | 같은 부호의 형으로 맞춥니다. |
| 시간 제한이 되감김 순간에 오판 | 합으로 비교함 | 경과를 뺄셈으로 구합니다. |
