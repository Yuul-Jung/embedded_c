## 구조체는 멤버를 순서대로 늘어놓은 메모리

구조체는 멤버를 선언한 순서대로 메모리에 늘어놓은 것입니다. 컴파일러가 정렬을 맞추려고 멤버 사이에 빈 칸(패딩)을 넣습니다.

| 규칙 | 내용 |
|---|---|
| 배치 순서 | 멤버는 선언 순서대로 낮은 주소부터 놓입니다. 컴파일러가 순서를 바꾸지 않습니다. |
| 멤버 정렬 | 각 멤버는 자기 형의 정렬 배수 위치에 놓입니다. 필요하면 앞에 패딩이 들어갑니다. |
| 구조체 정렬 | 멤버 중 가장 큰 정렬 값을 따릅니다. 중첩 구조체도 같습니다. `header`는 2, `message`는 4입니다. |
| 구조체 크기 | 구조체 정렬의 배수입니다. 마지막 멤버 뒤에도 패딩이 들어갑니다. |

{{svg:figures/ch04_fig01.svg|struct message의 20바이트 배치. 점선이 패딩입니다.}}

**코드 C-1 · 중첩 구조체의 크기와 멤버 위치** · 파일: `src/test_struct.c` · 검증: PC(gcc) 컴파일·실행 통과, 보드 미검증

```c
/* C-1. 중첩 구조체의 크기와 멤버 위치 */
struct header {
    uint8_t  type;
    uint8_t  len;
    uint16_t seq;
};

struct message {
    uint8_t       id;
    struct header hdr;          /* 정렬은 4가 아니라 2 (가장 큰 멤버가 uint16_t) */
    uint32_t      payload[2];
    uint8_t       crc;
};

static void demo_layout(void)
{
    printf("[C-1] header : sizeof=%zu alignof=%zu\n",
           sizeof(struct header), _Alignof(struct header));
    printf("      message: sizeof=%zu alignof=%zu\n",
           sizeof(struct message), _Alignof(struct message));
    printf("      offset id=%zu hdr=%zu payload=%zu crc=%zu\n",
           offsetof(struct message, id),
           offsetof(struct message, hdr),
           offsetof(struct message, payload),
           offsetof(struct message, crc));
}
```

**실행 결과 (PC에서 실제 실행)**

```text
[C-1] header : sizeof=4 alignof=2
      message: sizeof=20 alignof=4
      offset id=0 hdr=2 payload=8 crc=16
```

`id` 뒤 1바이트는 `hdr`를 2바이트 정렬에 맞추는 패딩이고, `hdr` 뒤 2바이트는 `payload`를 4바이트 정렬에 맞추는 패딩입니다. `crc` 뒤 3바이트는 전체 크기를 4의 배수로 맞춥니다. 멤버 합은 14바이트이지만 크기는 20바이트입니다.

**코드 C-2 · 멤버 주소와 -> 접근** · 파일: `src/test_struct.c` · 검증: PC(gcc) 컴파일·실행 통과, 보드 미검증

```c
/* C-2. 멤버 주소 = 구조체 시작 주소 + 오프셋, 그리고 -> 접근 */
static void demo_member_addr(void)
{
    struct message m = {0};
    const uint8_t *base = (const uint8_t *)&m;
    int same = ((const uint8_t *)&m.payload[1] ==
                base + offsetof(struct message, payload) + sizeof(uint32_t));

    struct message *pm = &m;              /* 구조체 포인터 */
    pm->hdr.seq = 0x1234u;                /* (*pm).hdr.seq 와 같은 표기 */
    pm->payload[1] = 0xCAFEu;

    printf("[C-2] &m.payload[1] == base + offset + 4 ? %s\n", same ? "참" : "거짓");
    printf("      m.hdr.seq=0x%04X m.payload[1]=0x%04X\n",
           (unsigned)m.hdr.seq, (unsigned)m.payload[1]);
}
```

**실행 결과 (PC에서 실제 실행)**

```text
[C-2] &m.payload[1] == base + offset + 4 ? 참
      m.hdr.seq=0x1234 m.payload[1]=0xCAFE
```

| 표기 | 뜻 |
|---|---|
| `s.m` | 구조체 변수 `s`의 멤버 `m` |
| `p->m` | 구조체 포인터 `p`가 가리키는 구조체의 멤버 `m` (`(*p).m`과 같음) |

**코드 C-3 · 초기화, 대입, 포인터 전달** · 파일: `src/test_struct.c` · 검증: PC(gcc) 컴파일·실행 통과, 보드 미검증

```c
/* C-3. 초기화, 대입(복사), 포인터 전달 */
static void bump(struct header *h)
{
    h->seq += 1;
}

static void demo_init_pass(void)
{
    struct header h = { .type = 1, .len = 8, .seq = 0x0100u };  /* 지정 초기화 */
    struct header copy = h;                                      /* 대입은 바이트 복사 */
    struct header zero = { .type = 9 };                          /* 나머지 멤버는 0 */

    bump(&h);

    printf("[C-3] h   : type=%u len=%u seq=0x%04X\n",
           (unsigned)h.type, (unsigned)h.len, (unsigned)h.seq);
    printf("      copy: type=%u len=%u seq=0x%04X\n",
           (unsigned)copy.type, (unsigned)copy.len, (unsigned)copy.seq);
    printf("      zero: type=%u len=%u seq=0x%04X\n",
           (unsigned)zero.type, (unsigned)zero.len, (unsigned)zero.seq);
}
```

**실행 결과 (PC에서 실제 실행)**

```text
[C-3] h   : type=1 len=8 seq=0x0101
      copy: type=1 len=8 seq=0x0100
      zero: type=9 len=0 seq=0x0000
```

구조체의 대입과 값 전달은 전체를 복사합니다. 큰 구조체는 포인터로 넘깁니다.

> **함정** 구조체를 바이트 배열로 통째로 송수신하면 패딩 위치와 엔디안이 MCU·컴파일러마다 달라질 수 있습니다. 통신 패킷은 멤버별로 바이트를 직접 채웁니다.

## 레지스터 맵을 구조체로 덮어씌우기

주변장치 레지스터는 기준 주소에서 오프셋 순서로 놓여 있습니다. 같은 배치의 구조체를 그 주소에 덮어씌우면 레지스터를 멤버 이름으로 접근할 수 있습니다.

{{svg:figures/ch04_fig02.svg|예시용 가상 타이머 장치의 레지스터 블록. 데이터시트의 오프셋과 구조체의 멤버 위치가 일치해야 합니다.}}

**코드 C-4 · 레지스터 맵 구조체와 오프셋 검증** · 파일: `src/test_struct.c` · 검증: PC(gcc) 컴파일·실행 통과, 보드 미검증

```c
/* C-4. 가상 타이머 장치의 레지스터 블록 (예시용 장치) */
typedef struct {
    volatile uint32_t CTRL;          /* 0x00 제어 */
    volatile uint32_t STATUS;        /* 0x04 상태 */
    volatile uint32_t LOAD;          /* 0x08 초기값 */
    volatile uint32_t COUNT;         /* 0x0C 현재값 */
    uint32_t          reserved[4];   /* 0x10~0x1C 예약 영역 */
    volatile uint32_t INTMASK;       /* 0x20 인터럽트 마스크 */
} timer_regs_t;

/* 데이터시트의 오프셋과 다르면 컴파일이 멈춘다 */
_Static_assert(offsetof(timer_regs_t, STATUS)  == 0x04, "STATUS 오프셋");
_Static_assert(offsetof(timer_regs_t, LOAD)    == 0x08, "LOAD 오프셋");
_Static_assert(offsetof(timer_regs_t, COUNT)   == 0x0C, "COUNT 오프셋");
_Static_assert(offsetof(timer_regs_t, INTMASK) == 0x20, "INTMASK 오프셋");
_Static_assert(sizeof(timer_regs_t) == 0x24, "블록 크기");

static timer_regs_t fake_timer;                    /* PC: 가짜 레지스터 블록 */
#define TIMER ((timer_regs_t *)&fake_timer)        /* 보드: ((timer_regs_t *)기준주소) */

static void demo_regmap(void)
{
    TIMER->LOAD     = 1000u;
    TIMER->CTRL    |= 0x1u;                        /* 읽기-수정-쓰기 */
    TIMER->INTMASK  = 0x3u;

    printf("[C-4] offset STATUS=0x%02zX LOAD=0x%02zX INTMASK=0x%02zX sizeof=0x%02zX\n",
           offsetof(timer_regs_t, STATUS), offsetof(timer_regs_t, LOAD),
           offsetof(timer_regs_t, INTMASK), sizeof(timer_regs_t));
    printf("      LOAD=%u CTRL=0x%X INTMASK=0x%X\n",
           (unsigned)TIMER->LOAD, (unsigned)TIMER->CTRL, (unsigned)TIMER->INTMASK);
}
```

**실행 결과 (PC에서 실제 실행)**

```text
[C-4] offset STATUS=0x04 LOAD=0x08 INTMASK=0x20 sizeof=0x24
      LOAD=1000 CTRL=0x1 INTMASK=0x3
```

`_Static_assert`는 조건이 거짓이면 컴파일을 멈춥니다. 오프셋과 블록 크기를 데이터시트 값으로 적어 두면, 멤버를 잘못 나열했을 때 보드에서 헤매기 전에 빌드 단계에서 잡힙니다. 예약 영역은 `reserved[]`로 채웁니다.

**코드 C-5 · 예약 영역을 빼먹은 잘못된 정의** · 파일: `src/test_struct.c` · 검증: PC(gcc) 컴파일·실행 통과, 보드 미검증

```c
/* C-5. 예약 영역을 빼먹은 잘못된 정의 (offset이 어긋난다) */
struct bad_timer_regs {
    uint32_t CTRL;
    uint32_t STATUS;
    uint32_t LOAD;
    uint32_t COUNT;
    uint32_t INTMASK;                              /* 0x20 이어야 하는데 */
};

static void demo_bad_regmap(void)
{
    printf("[C-5] bad INTMASK offset=0x%02zX (데이터시트: 0x20), sizeof=0x%02zX\n",
           offsetof(struct bad_timer_regs, INTMASK), sizeof(struct bad_timer_regs));
}
```

**실행 결과 (PC에서 실제 실행)**

```text
[C-5] bad INTMASK offset=0x10 (데이터시트: 0x20), sizeof=0x14
```

### REG32 방식과 구조체 방식

| 방식 | 쓰기 예 | 장점 | 주의 |
|---|---|---|---|
| `REG32` + 오프셋 매크로 | `REG32(TIMER_BASE + TIMER_LOAD) = 1000u;` | 패딩 규칙이 필요 없고 어느 컴파일러에서나 같게 동작 | 레지스터마다 오프셋 매크로를 따로 관리 |
| 구조체 | `TIMER->LOAD = 1000u;` | 멤버 이름으로 접근하고, 오프셋을 컴파일러가 계산해 검증 가능 | 예약 영역과 패딩 규칙을 알아야 함 |

> **읽기-수정-쓰기** `TIMER->CTRL |= 0x1u`는 읽고, 비트를 바꾸고, 다시 쓰는 3단계입니다. 상태 비트가 읽기만으로 바뀌는 레지스터에서는 부작용이 생길 수 있어 기법 11에서 다시 다룹니다. 이 시리즈의 드라이버는 `REG32` + 오프셋 매크로(`soc_map.h`) 방식입니다.

### 자주 겪는 문제

| 증상 | 원인 | 조치 |
|---|---|---|
| 레지스터가 엉뚱한 주소에 쓰임 | 멤버 나열이 데이터시트 오프셋과 어긋남 (예약 영역 누락) | `reserved[]`로 채우고 `_Static_assert`로 오프셋을 검증합니다. |
| 8·16비트 멤버를 섞었더니 오프셋이 밀림 | 정렬을 맞추려고 패딩이 들어감 | 레지스터 폭과 같은 형을 쓰고 오프셋을 검증합니다. |
| `packed`로 맞췄더니 동작이 이상함 | `packed`는 컴파일러 확장이며 비정렬 접근을 만들 수 있음 | 레지스터 블록에는 쓰지 않고 `reserved[]`로 오프셋을 맞춥니다. |
| `timer_regs_t t;`로 선언하고 읽었더니 값이 안 변함 | 장치가 아니라 일반 메모리에 만든 복사본 | 기준 주소를 구조체 포인터로 변환해 접근합니다. |
