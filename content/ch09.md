## 무한 대기를 막는 폴링과 타임아웃

**S등급** 폴링(Polling)은 상태 레지스터를 반복해서 읽어 장치가 준비되었는지 확인하는 방식입니다. 장치가 응답하지 않으면 영원히 기다리므로, 모든 폴링 루프에 끝나는 조건(타임아웃)을 함께 씁니다.

**코드 4-1 · 시험용 가상 장치** · 파일: `src/test_poll.c` · 검증: PC(gcc) 컴파일·실행 통과, 보드 미검증

```c
/* 4-1. 시험용 가상 장치 (보드에서는 status_read()를 REG32(STATUS 주소)로, ticks_now()를 타이머 틱으로 바꾼다) */
#define ST_READY  0x1u            /* STATUS bit0: 준비됨 */
#define ST_ERROR  0x2u            /* STATUS bit1: 오류 */

#define RC_OK          0
#define RC_TIMEOUT   (-1)
#define RC_DEVICE    (-2)

static uint32_t sim_tick;         /* 가상 틱 (상태를 읽을 때마다 1 증가) */
static uint32_t sim_reads;        /* 상태를 읽은 횟수 */
static uint32_t sim_ready_after;  /* 이 횟수째 읽을 때 준비 비트가 올라간다 */
static uint32_t sim_error_after;  /* 이 횟수째 읽을 때 오류 비트가 올라간다 (0이면 오류 없음) */

static uint32_t status_read(void)
{
    uint32_t st = 0u;

    sim_tick++;
    sim_reads++;
    if (sim_reads >= sim_ready_after) {
        st |= ST_READY;
    }
    if (sim_error_after != 0u && sim_reads >= sim_error_after) {
        st |= ST_ERROR;
    }
    return st;
}

static uint32_t ticks_now(void)
{
    return sim_tick;
}

static void sim_reset(uint32_t tick0, uint32_t ready_after, uint32_t error_after)
{
    sim_tick = tick0;
    sim_reads = 0u;
    sim_ready_after = ready_after;
    sim_error_after = error_after;
}

static const char *rc_name(int rc)
{
    return (rc == RC_OK) ? "OK" : (rc == RC_TIMEOUT) ? "TIMEOUT" : "DEVICE";
}
```

상태를 읽을 때마다 1틱이 흐르고, 정해진 횟수째에 준비 비트가 올라가는 가상 장치입니다. 보드에서는 `status_read()`를 `REG32` 접근으로, `ticks_now()`를 타이머 틱으로 바꿉니다.

**코드 4-2 · 타임아웃 없는 대기** · 파일: `src/test_poll.c` · 검증: PC(gcc) 컴파일·실행 통과, 보드 미검증

```c
/* 4-2. 타임아웃 없는 대기: 장치가 응답하지 않으면 돌아오지 않는다 */
static void wait_ready_forever(void)
{
    while ((status_read() & ST_READY) == 0u) {
        /* 준비될 때까지 반복 */
    }
}

static void demo_forever(void)
{
    sim_reset(0u, 5u, 0u);                    /* 5번째 읽기에서 준비됨 */
    wait_ready_forever();
    printf("[4-2] 준비됨: 상태를 %u번 읽고 돌아옴\n", (unsigned)sim_reads);
}
```

**실행 결과 (PC에서 실제 실행)**

```text
[4-2] 준비됨: 상태를 5번 읽고 돌아옴
```

장치가 응답하지 않으면 이 함수는 돌아오지 않습니다. 장치를 뽑거나 배선이 끊어지면 시스템 전체가 멈춥니다. 이 상태로는 응답 없는 장치를 시험할 수 없어서 준비되는 경우만 실행했습니다.

### 타임아웃을 거는 두 가지 방법

| 방법 | 장점 | 단점 |
|---|---|---|
| 반복 횟수로 제한 | 타이머 없이 쓸 수 있음 (부팅 초기에도 가능) | 같은 횟수가 걸리는 시간이 CPU 속도, 최적화 수준, 인터럽트에 따라 달라짐 |
| 틱 시간으로 제한 | 실제 시간 기준이라 CPU와 빌드 설정에 무관 | 틱 타이머가 필요하고, 틱이 되감겨도 맞게 계산해야 함(기법 3) |

**코드 4-3 · 반복 횟수로 제한** · 파일: `src/test_poll.c` · 검증: PC(gcc) 컴파일·실행 통과, 보드 미검증

```c
/* 4-3. 반복 횟수로 제한 */
static int wait_ready_count(uint32_t max_loops)
{
    while (max_loops-- != 0u) {
        if ((status_read() & ST_READY) != 0u) {
            return RC_OK;
        }
    }
    return RC_TIMEOUT;
}

static void demo_count(void)
{
    int rc;

    sim_reset(0u, 5u, 0u);
    rc = wait_ready_count(10u);
    printf("[4-3] 5번째에 준비, 최대 10회: %s (읽은 횟수=%u)\n", rc_name(rc), (unsigned)sim_reads);

    sim_reset(0u, 50u, 0u);
    rc = wait_ready_count(10u);
    printf("      50번째에 준비, 최대 10회: %s (읽은 횟수=%u)\n", rc_name(rc), (unsigned)sim_reads);
}
```

**실행 결과 (PC에서 실제 실행)**

```text
[4-3] 5번째에 준비, 최대 10회: OK (읽은 횟수=5)
      50번째에 준비, 최대 10회: TIMEOUT (읽은 횟수=10)
```

**코드 4-4 · 틱 시간으로 제한** · 파일: `src/test_poll.c` · 검증: PC(gcc) 컴파일·실행 통과, 보드 미검증

```c
/* 4-4. 틱 시간으로 제한 (경과는 뺄셈으로 구한다) */
static int wait_ready_ticks(uint32_t timeout_ticks)
{
    uint32_t start = ticks_now();

    for (;;) {
        if ((status_read() & ST_READY) != 0u) {          /* 상태를 먼저 보고 */
            return RC_OK;
        }
        if ((uint32_t)(ticks_now() - start) >= timeout_ticks) {   /* 시간은 나중에 본다 */
            return RC_TIMEOUT;
        }
    }
}

static void demo_ticks(void)
{
    static const struct { uint32_t tick0, ready_after; const char *note; } cases[4] = {
        { 0x00000000u,   5u, "5번째에 준비" },
        { 0x00000000u,  50u, "50번째에 준비" },
        { 0xFFFFFFFCu, 100u, "틱이 되감기는 구간에서 시작, 준비되지 않음" },
        { 0x00000000u,  10u, "제한과 같은 10번째에 준비" },
    };

    printf("[4-4] 제한 10틱\n");
    for (int i = 0; i < 4; i++) {
        sim_reset(cases[i].tick0, cases[i].ready_after, 0u);
        int rc = wait_ready_ticks(10u);
        printf("      %s: %s (읽은 횟수=%u)\n", cases[i].note, rc_name(rc), (unsigned)sim_reads);
    }
}
```

**실행 결과 (PC에서 실제 실행)**

```text
[4-4] 제한 10틱
      5번째에 준비: OK (읽은 횟수=5)
      50번째에 준비: TIMEOUT (읽은 횟수=10)
      틱이 되감기는 구간에서 시작, 준비되지 않음: TIMEOUT (읽은 횟수=10)
      제한과 같은 10번째에 준비: OK (읽은 횟수=10)
```

경과 시간을 뺄셈으로 구하므로 틱이 되감기는 구간에서도 맞습니다(셋째 줄). 상태를 먼저 읽고 시간을 나중에 확인하므로, 제한 시간에 정확히 준비된 경우(마지막 줄)도 성공으로 처리합니다.

## 준비, 오류, 시간 초과를 함께 처리

대기 결과는 성공, 장치 오류, 시간 초과 세 가지로 나뉩니다. 함수는 이 결과를 반환 값으로 알리고, 재시도와 복구는 호출한 쪽이 정합니다.

{{svg:figures/ch09_fig01.svg|판단 순서는 오류, 준비, 시간입니다. 상태를 먼저 판단하고 시간을 마지막에 확인합니다.}}

**코드 4-5 · 준비, 오류, 시간 초과를 함께 처리** · 파일: `src/test_poll.c` · 검증: PC(gcc) 컴파일·실행 통과, 보드 미검증

```c
/* 4-5. 준비, 오류, 시간 초과를 함께 처리 */
static int wait_ready_or_error(uint32_t timeout_ticks)
{
    uint32_t start = ticks_now();

    for (;;) {
        uint32_t st = status_read();                    /* 한 번 읽어 변수에 담아 판단한다 */

        if ((st & ST_ERROR) != 0u) {
            return RC_DEVICE;
        }
        if ((st & ST_READY) != 0u) {
            return RC_OK;
        }
        if ((uint32_t)(ticks_now() - start) >= timeout_ticks) {
            return RC_TIMEOUT;
        }
    }
}

static void demo_status(void)
{
    int rc;

    sim_reset(0u, 5u, 0u);
    rc = wait_ready_or_error(10u);
    printf("[4-5] 5번째에 준비: %s (읽은 횟수=%u)\n", rc_name(rc), (unsigned)sim_reads);

    sim_reset(0u, 100u, 3u);
    rc = wait_ready_or_error(10u);
    printf("      3번째에 오류: %s (읽은 횟수=%u)\n", rc_name(rc), (unsigned)sim_reads);

    sim_reset(0u, 100u, 0u);
    rc = wait_ready_or_error(10u);
    printf("      준비되지 않음: %s (읽은 횟수=%u)\n", rc_name(rc), (unsigned)sim_reads);
}
```

**실행 결과 (PC에서 실제 실행)**

```text
[4-5] 5번째에 준비: OK (읽은 횟수=5)
      3번째에 오류: DEVICE (읽은 횟수=3)
      준비되지 않음: TIMEOUT (읽은 횟수=10)
```

상태는 한 번 읽어 변수 `st`에 담고 그 값으로 오류와 준비를 모두 판단합니다. 읽으면 상태가 바뀌는 레지스터에서도 값이 어긋나지 않습니다(기법 2).

**코드 4-6 · 시간 초과일 때만 다시 시도** · 파일: `src/test_poll.c` · 검증: PC(gcc) 컴파일·실행 통과, 보드 미검증

```c
/* 4-6. 시간 초과일 때만 다시 시도 */
static int wait_with_retry(uint32_t timeout_ticks, int max_try, int *tries)
{
    int rc = RC_TIMEOUT;

    *tries = 0;
    while (*tries < max_try && rc == RC_TIMEOUT) {      /* 장치 오류는 다시 시도하지 않는다 */
        rc = wait_ready_or_error(timeout_ticks);
        (*tries)++;
    }
    return rc;
}

static void demo_retry(void)
{
    int tries;
    int rc;

    sim_reset(0u, 25u, 0u);                              /* 느린 장치: 25번째에 준비 */
    rc = wait_with_retry(10u, 3, &tries);
    printf("[4-6] 느린 장치: %s (시도=%d, 읽은 횟수=%u)\n", rc_name(rc), tries, (unsigned)sim_reads);

    sim_reset(0u, 100u, 0u);                             /* 응답 없는 장치 */
    rc = wait_with_retry(10u, 3, &tries);
    printf("      응답 없음: %s (시도=%d, 읽은 횟수=%u)\n", rc_name(rc), tries, (unsigned)sim_reads);

    sim_reset(0u, 100u, 2u);                             /* 오류를 알리는 장치 */
    rc = wait_with_retry(10u, 3, &tries);
    printf("      장치 오류: %s (시도=%d, 읽은 횟수=%u)\n", rc_name(rc), tries, (unsigned)sim_reads);
}
```

**실행 결과 (PC에서 실제 실행)**

```text
[4-6] 느린 장치: OK (시도=3, 읽은 횟수=25)
      응답 없음: TIMEOUT (시도=3, 읽은 횟수=30)
      장치 오류: DEVICE (시도=1, 읽은 횟수=2)
```

느린 장치는 시도를 거듭해 성공하고, 응답 없는 장치는 시도 횟수를 다 쓰고 시간 초과로 끝납니다. 장치 오류는 기다린다고 해결되지 않으므로 다시 시도하지 않고 바로 돌려줍니다.

### 타임아웃 값 정하기

| 대기 대상 | 최대 소요 시간의 근거 |
|---|---|
| UART 1바이트 송신 (115200 bps, 8N1) | 시작 1 + 데이터 8 + 정지 1 = 10비트 ÷ 115200 ≈ 86.8 µs |
| I2C 1바이트 + ACK (100 kHz) | 9클록 ÷ 100 kHz = 90 µs (클록 스트레칭이 있으면 늘어남) |
| 센서 변환 완료 | 데이터시트의 최대 변환 시간 |

타임아웃은 이런 최대 소요 시간보다 여유 있게 길게 정하고, 값의 근거를 주석으로 남깁니다.

### 작성 규칙

| 규칙 | 이유 |
|---|---|
| 모든 폴링 루프에 끝나는 조건을 둔다 | 장치 고장이나 배선 불량에서 시스템이 멈추지 않음 |
| 상태를 한 번 읽어 변수에 담아 판단한다 | 읽으면 상태가 바뀌는 레지스터에서도 값이 일관됨(기법 2) |
| 상태를 먼저, 시간은 나중에 확인한다 | 제한 시간에 준비된 경우도 성공으로 처리 |
| 경과 시간은 뺄셈으로 구한다 | 틱이 되감겨도 맞음(기법 3) |
| 결과는 반환 값으로 알린다 | 호출한 쪽이 재시도, 복구, 기록을 결정 |
| 긴 대기는 폴링 대신 인터럽트나 논블로킹으로 | 대기하는 동안 CPU가 다른 일을 하지 못함(기법 5, 9) |

### 자주 겪는 문제

| 증상 | 원인 | 조치 |
|---|---|---|
| 장치를 뽑거나 배선이 불량이면 프로그램이 멈춤 | 타임아웃 없는 폴링 | 모든 폴링에 타임아웃을 둡니다. |
| 최적화 빌드에서 타임아웃이 너무 짧아짐 | 반복 횟수 기반 제한 (같은 횟수가 더 빨리 끝남) | 틱 시간 기반으로 바꿉니다. |
| 제한 시간 직전에 준비되었는데 실패로 처리 | 시간을 먼저 확인함 | 상태를 먼저, 시간을 나중에 확인합니다. |
| 오래 가동한 뒤 가끔 타임아웃이 잘못 판단됨 | 합으로 비교 (1 ms 틱이면 약 49.7일마다 되감김) | 뺄셈으로 경과를 구합니다(기법 3). |
| 폴링 루프가 최적화로 사라지거나 멈춤 | 레지스터 접근에 `volatile`이 빠짐 | 기법 2 |
| 타임아웃 뒤 장치가 이상한 상태로 남음 | 실패 처리에서 장치를 초기 상태로 되돌리지 않음 | 시간 초과 처리에 장치 초기화를 포함합니다. |
