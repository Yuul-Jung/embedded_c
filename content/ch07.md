## volatile: 컴파일러가 접근을 지우지 못하게 하기

**S등급** 컴파일러는 메모리 접근을 "이 프로그램 안에서만 값이 바뀐다"고 가정하고 줄입니다. 레지스터는 장치가 값을 바꾸므로 이 가정이 틀립니다. `volatile`은 해당 접근을 소스에 적은 횟수와 순서대로 수행하라는 표시입니다.

### 컴파일러가 하는 최적화와 레지스터에서 생기는 문제

| 최적화 | 컴파일러의 가정 | 레지스터에서 생기는 문제 |
|---|---|---|
| 읽기를 루프 밖으로 이동 | 루프 안에서 이 메모리를 바꾸는 코드가 없다 | 상태 비트를 한 번만 읽고 영원히 대기 |
| 연속 쓰기를 마지막 한 번으로 합침 | 앞의 쓰기는 읽히기 전에 덮어써진다 | 첫 번째 명령이나 데이터가 장치에 전달되지 않음 |
| 연속 읽기를 한 번으로 합침 | 두 읽기 사이에 값이 바뀌지 않는다 | 두 번째 읽기(새 데이터)가 사라짐 |

{{svg:figures/ch07_fig01.svg|상태 비트를 기다리는 폴링 루프. volatile이 없으면 컴파일러가 읽기를 루프 밖으로 옮깁니다.}}

**코드 2-1 · 상태 비트를 기다리는 폴링 루프** · 파일: `src/test_vol.c` · 검증: PC(gcc) 컴파일·실행 통과, 보드 미검증

```c
/* 2-1. 상태 비트를 기다리는 폴링 루프 */
uint32_t wait_plain(const uint32_t *status)
{
    while ((*status & 1u) == 0u) {
        /* 비트 0이 1이 될 때까지 반복 */
    }
    return *status;
}

uint32_t wait_volatile(const volatile uint32_t *status)
{
    while ((*status & 1u) == 0u) {
        /* 비트 0이 1이 될 때까지 반복 */
    }
    return *status;
}
```

**volatile 없음 (clang 실제 생성 결과)**

```asm
wait_plain:
    lw    a0, 0(a0)
    andi  a1, a0, 1
    bnez  a1, .LBB0_2
.LBB0_1:
    j     .LBB0_1
.LBB0_2:
    ret
```

**volatile 있음 (clang 실제 생성 결과)**

```asm
wait_volatile:
.LBB1_1:
    lw    a1, 0(a0)
    andi  a1, a1, 1
    beqz  a1, .LBB1_1
    lw    a0, 0(a0)
    ret
```

volatile이 없는 쪽은 상태를 한 번만 읽고(`lw`) 같은 값을 검사하다가, 비트가 0이면 자기 자신으로 점프(`j`)하며 영원히 돕니다. volatile이 있는 쪽은 반복할 때마다 `lw`로 다시 읽습니다.

> **함정** 최적화를 끄면(`-O0`) 같은 코드가 반복마다 읽기를 수행해서 증상이 나타나지 않습니다. 디버그 빌드에서는 되고 최적화한 빌드에서만 멈추는 문제가 대표적인 증상입니다. PC의 gcc(x86-64, `-O2`)에서도 같은 패턴을 확인했습니다.

## 쓰기와 읽기의 횟수

레지스터에서는 접근 한 번이 곧 동작 한 번입니다. 쓰기 한 번은 명령 한 번, 읽기 한 번은 데이터 한 번을 뜻할 수 있어서 접근 횟수가 소스와 같아야 합니다.

**코드 2-2 · 같은 레지스터에 연속으로 쓰기** · 파일: `src/test_vol.c` · 검증: PC(gcc) 컴파일·실행 통과, 보드 미검증

```c
/* 2-2. 같은 레지스터에 연속으로 쓰기 */
void send2_plain(uint32_t *tx)
{
    *tx = 0x41u;
    *tx = 0x42u;
}

void send2_volatile(volatile uint32_t *tx)
{
    *tx = 0x41u;
    *tx = 0x42u;
}
```

**volatile 없음 (clang 실제 생성 결과)**

```asm
send2_plain:
    li    a1, 66
    sw    a1, 0(a0)
    ret
```

**volatile 있음 (clang 실제 생성 결과)**

```asm
send2_volatile:
    li    a1, 65
    sw    a1, 0(a0)
    li    a1, 66
    sw    a1, 0(a0)
    ret
```

**코드 2-3 · 같은 레지스터를 연속으로 읽기** · 파일: `src/test_vol.c` · 검증: PC(gcc) 컴파일·실행 통과, 보드 미검증

```c
/* 2-3. 같은 레지스터를 연속으로 읽기 */
uint32_t read2_plain(const uint32_t *rx)
{
    uint32_t a = *rx;
    uint32_t b = *rx;
    return a + b;
}

uint32_t read2_volatile(const volatile uint32_t *rx)
{
    uint32_t a = *rx;
    uint32_t b = *rx;
    return a + b;
}
```

**volatile 없음 (clang 실제 생성 결과)**

```asm
read2_plain:
    lw    a0, 0(a0)
    slli  a0, a0, 1
    ret
```

**volatile 있음 (clang 실제 생성 결과)**

```asm
read2_volatile:
    lw    a1, 0(a0)
    lw    a0, 0(a0)
    add   a0, a0, a1
    ret
```

**PC 실행 결과 · 값만 보면 두 버전이 같다**

```text
[2-2] t=0x42
[2-3] read2_plain=14 read2_volatile=14
```

volatile이 없는 쪽은 쓰기를 66(`0x42`) 한 번으로, 읽기를 한 번(`lw`)과 2배(`slli`, 왼쪽으로 1칸 이동)로 줄였습니다. 일반 변수라면 결과가 같아서 올바른 최적화이지만, 장치는 첫 번째 쓰기(65)를 받지 못하고 두 번째 읽기도 일어나지 않습니다. 차이는 값이 아니라 접근 횟수에서만 드러납니다.

### 레지스터 종류별 접근 주의

**컴파일 결과 · RISC-V rv32imc, clang 18.1.3, -O2**

| 종류 (예) | 접근의 의미 | 주의 |
|---|---|---|
| 상태 (읽기 전용) | 읽을 때마다 현재 장치 상태 | 매번 읽어야 최신 값. `const volatile`로 선언 |
| 수신 데이터 (읽으면 소모되는 FIFO류) | 읽기 한 번에 데이터가 하나 빠짐 | 두 번 읽으면 데이터 하나를 잃음. 한 번 읽어 변수에 담아 사용 |
| 송신 데이터 | 쓰기 한 번에 전송 한 번 | 쓰기를 합치거나 건너뛰면 안 됨 |
| 제어 (읽고 쓰기) | 설정을 유지하는 값 | 읽기-수정-쓰기 가능. 필드만 바꿉니다(기법 1) |
| 쓰면 지워지는 상태 (Write-1-to-Clear) | 1을 쓴 비트만 0으로 지워짐 | `\|=`로 쓰면 읽은 1이 그대로 다시 쓰여 다른 비트도 지워짐 |

접근 속성(읽기 전용 RO, 읽고 쓰기 RW, 쓰기 전용 WO, 쓰기로 지움 W1C 등)은 칩마다 다르므로 데이터시트의 레지스터 표로 확인합니다.

**코드 2-4 · 읽으면 소모되는 레지스터 (가상 장치)** · 파일: `src/test_vol.c` · 검증: PC(gcc) 컴파일·실행 통과, 보드 미검증

```c
/* 2-4. 읽으면 소모되는 레지스터는 한 번 읽어 변수에 담아 쓴다 (가상 장치) */
static const char rx_data[] = "ABC";
static size_t     rx_pos;

static uint32_t rx_reg_read(void)    /* 읽을 때마다 글자 하나가 빠지는 가상 RX 레지스터 */
{
    return (uint32_t)(unsigned char)rx_data[rx_pos < 3u ? rx_pos++ : 3u];
}

static void demo_pop(void)
{
    uint32_t used = 0u;

    rx_pos = 0u;
    if (rx_reg_read() >= 'A') {      /* 첫 읽기: 판단에만 쓰고 버려진다 */
        used = rx_reg_read();        /* 두 번째 읽기: 다음 글자가 나온다 */
    }
    printf("[2-4] 두 번 읽으면: 사용한 글자=%c, FIFO에 남은 글자=%zu\n",
           (char)used, 3u - rx_pos);

    rx_pos = 0u;
    uint32_t ch = rx_reg_read();     /* 한 번 읽어 변수에 담는다 */
    if (ch >= 'A') {
        used = ch;
    }
    printf("      한 번 읽으면: 사용한 글자=%c, FIFO에 남은 글자=%zu\n",
           (char)used, 3u - rx_pos);
}
```

**실행 결과 (PC에서 실제 실행)**

```text
[2-4] 두 번 읽으면: 사용한 글자=B, FIFO에 남은 글자=1
      한 번 읽으면: 사용한 글자=A, FIFO에 남은 글자=2
```

같은 레지스터를 판단용과 사용용으로 두 번 읽으면, 판단한 글자(`A`)와 사용한 글자(`B`)가 달라지고 FIFO에서 글자가 하나 더 사라집니다. 읽은 값은 변수 하나에 담아 판단과 사용에 함께 씁니다.

## 레지스터 접근 코드 작성법

레지스터 주소를 가리키는 포인터는 `volatile`이 붙은 형으로 선언합니다. 읽기 전용 레지스터에는 `const`도 함께 붙입니다.

| 선언 | 읽는 법 | 용도 |
|---|---|---|
| `volatile uint32_t *p` | p가 가리키는 값이 volatile | 읽고 쓰는 레지스터 (가장 흔함) |
| `const volatile uint32_t *p` | p가 가리키는 값이 읽기 전용이면서 volatile | 읽기 전용 레지스터. 쓰면 컴파일 오류 |
| `volatile uint32_t *const p` | 포인터 자체는 고정, 가리키는 값은 volatile | 고정 주소의 레지스터 |
| `uint32_t *volatile p` | 포인터 변수 p 자체가 volatile | 레지스터 접근용이 아님. 레지스터 값에는 volatile이 적용되지 않음 |

`REG32(addr)`(기초 B)는 정의 안에 `volatile`이 들어 있어서 이 매크로로 접근하는 코드는 따로 신경 쓰지 않아도 됩니다.

**코드 2-5 · 읽기 전용·읽기 쓰기 레지스터 포인터와 REG32** · 파일: `src/test_vol.c` · 검증: PC(gcc) 컴파일·실행 통과, 보드 미검증

```c
/* 2-5. 레지스터 접근 매크로와 포인터 선언 */
#define REG32(addr)  (*(volatile uint32_t *)(uintptr_t)(addr))

static uint32_t fake_regs[2];                    /* 0:STATUS(읽기 전용) 1:TXDATA */

static void demo_reg(void)
{
    uintptr_t base = (uintptr_t)fake_regs;
    const volatile uint32_t *status = (const volatile uint32_t *)base;  /* 읽기 전용 레지스터 */
    volatile uint32_t       *txdata = (volatile uint32_t *)(base + 4u); /* 읽고 쓰는 레지스터 */

    fake_regs[0] = 0x1u;                         /* 장치가 상태 비트를 올렸다고 가정 */
    while ((*status & 0x1u) == 0u) {
        /* 준비될 때까지 대기 */
    }
    *txdata = 0x41u;
    REG32(base + 4u) |= 0x100u;                  /* 읽기-수정-쓰기 */

    printf("[2-5] STATUS=0x%X TXDATA=0x%X\n", (unsigned)*status, (unsigned)*txdata);
}
```

**실행 결과 (PC에서 실제 실행)**

```text
[2-5] STATUS=0x1 TXDATA=0x141
```

**코드 2-6 · 읽기 전용 레지스터에 쓰기 (의도한 오류)** · 파일: `src/ro_err.c` · 검증: PC(gcc) 컴파일·실행 통과, 보드 미검증

```c
void bad(const volatile uint32_t *status)
{
    *status = 0u;
}
```

**컴파일 결과 · gcc**

```text
error: assignment of read-only location ‘*status’
```

쓸 수 없는 레지스터에 실수로 쓰는 코드는 보드에서 헤매기 전에 컴파일 단계에서 잡힙니다.

### volatile이 해 주지 않는 일

| 기대 | 실제 | 조치 |
|---|---|---|
| `\|=`가 한 번에 실행된다 | 읽기, 수정, 쓰기 세 단계이며 그 사이에 인터럽트가 끼어들 수 있음 | 기법 11(임계 구역 보호) |
| 일반 변수 접근과의 순서도 지켜진다 | 다른 volatile 접근과의 순서만 지켜짐. 일반 변수 접근은 컴파일러가 옮길 수 있음 | 순서가 필요하면 배리어(장벽)를 사용합니다. 이 교과의 범위 밖 |
| 캐시나 쓰기 버퍼를 우회한다 | 컴파일러 최적화만 막고 CPU 하드웨어 동작은 바꾸지 않음 | 캐시가 있는 시스템은 별도 설정 |

### 자주 겪는 문제

| 증상 | 원인 | 조치 |
|---|---|---|
| 디버그 빌드에서는 되는데 최적화한 빌드에서 멈춤 | 상태 레지스터 포인터에 volatile이 빠짐 | 포인터 선언과 매크로를 확인합니다. |
| 송신 레지스터에 두 번 썼는데 장치에는 한 번만 전달 | volatile이 빠져 연속 쓰기가 합쳐짐 | `volatile`로 접근합니다. |
| `(uint32_t *)p`로 형을 바꿨더니 다시 최적화됨 | 캐스트로 volatile이 떨어져 나감 | 캐스트할 때 `volatile`을 유지합니다. |
| volatile을 붙였는데 ISR과 공유하는 변수 값이 가끔 깨짐 | volatile은 원자성을 보장하지 않음 | 기법 5, 11 |
