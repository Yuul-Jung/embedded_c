## 기다리지 않고 시간 확인하기

**A등급** `delay_ms()`처럼 시간이 찰 때까지 멈춰 기다리는 방식을 블로킹(Blocking, 막힘)이라 합니다. 기다리는 동안 CPU는 버튼도 통신도 보지 못합니다. 논블로킹(Non-blocking)은 메인 루프를 계속 돌면서 현재 시각을 확인하고, 기한이 된 일만 처리합니다.

{{svg:figures/ch14_fig01.svg|120 ms에 버튼이 눌렸을 때 처리하는 시각. 블로킹은 대기가 끝난 500 ms에, 논블로킹은 바로 처리합니다.}}

**코드 9-1 · 블로킹 대기와 논블로킹 루프 (가상 시간)** · 파일: `src/test_time.c` · 검증: PC(gcc) 컴파일·실행 통과, 보드 미검증

```c
/* 9-1. 기다리는 방식과 확인하는 방식 */
static uint32_t sim_ms;                       /* 가상 시간 (ms) */

static uint32_t now_ms(void)
{
    return sim_ms;
}

static bool time_due(uint32_t now, uint32_t deadline)   /* 기한이 지났는가 (되감김에도 맞다) */
{
    return (int32_t)(now - deadline) >= 0;
}

#define EVENT_AT  120u                        /* 버튼이 눌리는 시각 */

static bool button_down(void)
{
    return time_due(now_ms(), EVENT_AT);
}

static void delay_ms(uint32_t ms)             /* 블로킹: 시간이 찰 때까지 다른 일을 못 한다 */
{
    uint32_t start = now_ms();

    while ((uint32_t)(now_ms() - start) < ms) {
        sim_ms++;                             /* 가상 시간이 1 ms 흐른다 */
    }
}

static uint32_t run_blocking(void)
{
    sim_ms = 0u;
    for (;;) {
        /* LED 반전 */
        delay_ms(500u);                       /* 500 ms 동안 버튼을 보지 못한다 */
        if (button_down()) {
            return now_ms();
        }
    }
}

static uint32_t run_nonblocking(void)
{
    uint32_t next_blink = 500u;

    sim_ms = 0u;
    for (;;) {
        sim_ms++;                             /* 메인 루프 한 바퀴 (1 ms) */
        if (button_down()) {
            return now_ms();
        }
        if (time_due(now_ms(), next_blink)) {
            /* LED 반전 */
            next_blink += 500u;
        }
    }
}

static void demo_block(void)
{
    uint32_t a = run_blocking();
    uint32_t b = run_nonblocking();

    printf("[9-1] 버튼은 %u ms에 눌림: 블로킹 방식이 처리한 시각=%u ms, 논블로킹 방식=%u ms\n",
           (unsigned)EVENT_AT, (unsigned)a, (unsigned)b);
}
```

**실행 결과 (PC에서 실제 실행)**

```text
[9-1] 버튼은 120 ms에 눌림: 블로킹 방식이 처리한 시각=500 ms, 논블로킹 방식=120 ms
```

블로킹 방식은 버튼 처리가 대기 시간만큼 늦어집니다. 논블로킹 방식은 루프 한 바퀴가 짧으면 거의 바로 처리합니다. 논블로킹 방식에서 일이 길어지면 루프 한 바퀴가 늘어나므로, 한 번에 오래 걸리는 일은 기법 8의 상태 머신으로 나누어 한 걸음씩 진행합니다.

### 기한이 지났는지 비교하기

`time_due()`는 `(int32_t)(now - deadline) >= 0`으로 비교합니다. 부호 없는 뺄셈은 틱이 되감겨도 올바른 차이를 주고(기법 3), 그 차이를 부호 있는 값으로 읽으면 "기한이 지났는가"를 알 수 있습니다. 기한까지의 간격이 2³¹ ms(약 24.9일)보다 짧을 때 맞습니다. 부호 없는 값을 부호 있는 값으로 바꾸는 동작은 C 표준에서 구현 정의이며, 2의 보수를 쓰는 일반적인 컴파일러(이 책에서는 gcc로 확인)에서 이 코드처럼 동작합니다.

## 주기 작업과 틱 되감김

주기 작업은 다음 기한을 "이전 기한 + 주기"로 정합니다. "지금 시각 + 주기"로 정하면 처리가 늦은 만큼 시각이 계속 밀립니다.

**코드 9-2 · 기한에 더하기와 지금 시각에 더하기, 틱 되감김** · 파일: `src/test_time.c` · 검증: PC(gcc) 컴파일·실행 통과, 보드 미검증

```c
/* 9-2. 주기 작업: 다음 기한을 어떻게 정하는가 */
typedef struct {
    uint32_t period;
    uint32_t next;
} soft_timer_t;

static bool timer_fixed(soft_timer_t *t, uint32_t now)   /* 기한에 주기를 더한다 */
{
    if (!time_due(now, t->next)) {
        return false;
    }
    t->next += t->period;
    return true;
}

static bool timer_drift(soft_timer_t *t, uint32_t now)   /* 지금 시각에 주기를 더한다 */
{
    if (!time_due(now, t->next)) {
        return false;
    }
    t->next = now + t->period;
    return true;
}

static unsigned count_fires(bool (*f)(soft_timer_t *, uint32_t), uint32_t tick0)
{
    soft_timer_t t;
    uint32_t now = tick0;
    unsigned n = 0;

    t.period = 100u;
    t.next = tick0 + 100u;
    while ((uint32_t)(now - tick0) < 1000u) {
        if (f(&t, now)) {
            n++;
        }
        now += 30u;                           /* 한 바퀴에 30 ms 걸린다 */
    }
    return n;
}

static bool naive_due(uint32_t now, uint32_t deadline)   /* 되감김을 고려하지 않은 비교 */
{
    return now >= deadline;
}

static void demo_period(void)
{
    uint32_t start = 0xFFFFFFF0u;             /* 틱이 되감기기 직전 */
    uint32_t deadline = start + 100u;         /* 0x00000054로 되감긴다 */

    printf("[9-2] 100 ms 주기, 1000 ms 동안 (한 바퀴 30 ms): 기한에 더함=%u회, 지금 시각에 더함=%u회\n",
           count_fires(timer_fixed, 0u), count_fires(timer_drift, 0u));
    printf("      틱 0xFFFFFFF0에서 시작: 시작 직후 기한이 지났나? 부호 있는 비교=%d, 단순 비교=%d\n",
           (int)time_due(start, deadline), (int)naive_due(start, deadline));
}
```

**실행 결과 (PC에서 실제 실행)**

```text
[9-2] 100 ms 주기, 1000 ms 동안 (한 바퀴 30 ms): 기한에 더함=9회, 지금 시각에 더함=8회
      틱 0xFFFFFFF0에서 시작: 시작 직후 기한이 지났나? 부호 있는 비교=0, 단순 비교=1
```

한 바퀴가 30 ms 걸리는 루프에서 100 ms 주기 작업을 1000 ms 동안 돌렸습니다. 기한에 주기를 더하면 100, 200, ..., 900 ms의 기한이 모두 지켜져 9회 실행됩니다(1000 ms 지점은 구간 밖). 지금 시각에 주기를 더하면 매번 늦은 만큼 기한이 밀려 8회로 줄어듭니다.

틱이 `0xFFFFFFF0`에서 시작하면 기한 `시작 + 100`은 `0x00000054`로 되감깁니다. `now >= deadline`으로 비교하면 시작하자마자 기한이 지난 것으로 판단하고, 부호 있는 비교는 올바르게 "아직 아님"이라고 판단합니다(기법 3).

| 방식 | 다음 기한 | 특징 |
|---|---|---|
| 기한에 더함 | `next += period` | 한 번 늦어도 다음 기한은 원래 간격을 유지. 늦은 만큼 연속으로 따라잡아 실행될 수 있음 |
| 지금 시각에 더함 | `next = now + period` | 실행 간격이 보장되지만 평균 주기가 길어지고 시각이 밀림 |

기한에 더하는 방식은 오래 멈춘 뒤에 밀린 횟수만큼 연속으로 실행될 수 있습니다. 밀린 실행을 건너뛰어야 하면 기한이 지난 만큼 한 번에 건너뛰도록 따로 처리합니다.

### 작성 규칙

| 규칙 | 이유 |
|---|---|
| 기다리는 `delay` 대신 기한을 저장하고 매 루프에서 확인한다 | 기다리는 동안에도 다른 입력과 통신을 처리 |
| 시각 비교는 `(int32_t)(now - deadline) >= 0` | 틱이 되감겨도 맞음 (기법 3) |
| 주기 작업의 기한은 `next += period` | 처리가 늦어도 시각이 밀리지 않음 |
| 시각은 한 번 읽어 변수에 담아 쓴다 | 비교하는 사이 시각이 바뀌어 판단이 엇갈리지 않음 |
| 루프 한 바퀴를 짧게 유지한다 | 긴 일은 상태 머신으로 나눔 (기법 8) |
| 짧은 시간 대기가 꼭 필요하면 블로킹 대기를 허용하되 최대 시간을 정한다 | 하드웨어 사양상 몇 µs 대기가 필요한 경우가 있음 |

### 자주 겪는 문제

| 증상 | 원인 | 조치 |
|---|---|---|
| 대기 중에 버튼이나 통신이 늦게 반응 | `delay_ms()`가 CPU를 붙잡음 | 기한을 저장하고 루프에서 확인합니다(코드 9-1). |
| 주기가 점점 길어짐 | `next = now + period`로 늦은 만큼 시각이 밀림 | `next += period`로 바꿉니다(코드 9-2). |
| 약 49.7일 뒤 작업이 갑자기 연속 실행되거나 멈춤 | `now >= deadline`으로 비교해 틱 되감김에서 어긋남 | 부호 있는 차이로 비교합니다(코드 9-1). |
| 시간 확인 코드가 항상 참이거나 거짓 | `now_ms()`를 여러 번 읽어 서로 다른 값을 비교 | 한 번 읽은 값을 변수에 담아 비교합니다. |
| 오래 멈춘 뒤 작업이 연달아 여러 번 실행됨 | 기한이 밀린 횟수만큼 따라잡음 | 필요하면 밀린 기한을 건너뛰도록 처리합니다. |

> **시간원** `now_ms()`는 타이머 인터럽트가 올리는 틱 변수일 수도 있고 하드웨어 카운터를 읽는 함수일 수도 있습니다. 틱 변수를 ISR이 고치고 메인이 읽는 경우는 기법 5의 규칙(`volatile`, 쓰는 쪽 하나)을 따릅니다. 이 시리즈의 타이머 연결은 부록에 정리합니다.
