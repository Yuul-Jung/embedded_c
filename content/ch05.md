## 함수도 주소를 가진다

함수도 메모리에 놓인 코드이므로 시작 주소가 있습니다. 그 주소를 담은 변수가 함수 포인터이며, 어떤 함수를 부를지를 실행 중에 바꿀 수 있습니다.

### 선언 읽는 법

| 선언 | 뜻 |
|---|---|
| `void (*fp)(int)` | fp는 "int를 받아 void를 돌려주는 함수"의 포인터 |
| `void *fp(int)` | 괄호가 없으면 `void *`를 돌려주는 함수 `fp`의 선언 (포인터 변수가 아님) |
| `void (*tbl[3])(void)` | tbl은 "인자 없이 void를 돌려주는 함수"의 포인터 3개짜리 배열 |
| `typedef uint32_t (*binop_fn)(uint32_t, uint32_t);` | 긴 선언에 이름을 붙여 `binop_fn f;`처럼 짧게 사용 |

**코드 D-1 · 함수 포인터 선언, 대입, 호출** · 파일: `src/test_func.c` · 검증: PC(gcc) 컴파일·실행 통과, 보드 미검증

```c
/* D-1. 함수 포인터 선언, 대입, 호출 */
typedef uint32_t (*binop_fn)(uint32_t, uint32_t);

static uint32_t add_u32(uint32_t a, uint32_t b) { return a + b; }
static uint32_t and_u32(uint32_t a, uint32_t b) { return a & b; }

static void demo_fnptr(void)
{
    binop_fn f = add_u32;                /* 함수 이름은 함수의 시작 주소로 쓰인다 */
    uint32_t r1 = f(0xF0u, 0x0Fu);       /* (*f)(...) 와 같은 호출 */

    f = and_u32;                         /* 같은 형의 다른 함수로 바꿔 끼운다 */
    uint32_t r2 = f(0xF0u, 0x3Cu);

    printf("[D-1] add=0x%02X and=0x%02X f==and_u32 ? %s\n",
           (unsigned)r1, (unsigned)r2, (f == and_u32) ? "참" : "거짓");
}
```

**실행 결과 (PC에서 실제 실행)**

```text
[D-1] add=0xFF and=0x30 f==and_u32 ? 참
```

함수 이름을 그대로 대입하면 시작 주소가 들어가고, `f(...)`로 호출합니다. 같은 형(인자와 반환형이 같은 함수)이면 포인터를 바꿔 끼워 다른 함수를 부를 수 있습니다.

**코드 D-2 · 함수 포인터 테이블로 명령 분기** · 파일: `src/test_func.c` · 검증: PC(gcc) 컴파일·실행 통과, 보드 미검증

```c
/* D-2. 함수 포인터 테이블로 명령 분기 */
struct command {
    const char *name;
    void (*run)(int arg);
};

static int g_led = 0;
static void cmd_on(int arg)  { (void)arg; g_led = 1; }
static void cmd_off(int arg) { (void)arg; g_led = 0; }
static void cmd_set(int arg) { g_led = arg; }

static const struct command cmd_table[] = {
    { "on",  cmd_on  },
    { "off", cmd_off },
    { "set", cmd_set },
};

static int dispatch(const char *name, int arg)
{
    for (size_t i = 0; i < sizeof cmd_table / sizeof cmd_table[0]; i++) {
        if (strcmp(cmd_table[i].name, name) == 0) {
            cmd_table[i].run(arg);
            return 0;
        }
    }
    return -1;                           /* 없는 명령 */
}

static void demo_table(void)
{
    int r_on  = dispatch("on", 0);
    int led_a = g_led;
    int r_set = dispatch("set", 5);
    int led_b = g_led;
    int r_bad = dispatch("zzz", 0);
    int r_off = dispatch("off", 0);

    printf("[D-2] on=%d led=%d / set=%d led=%d / zzz=%d / off=%d led=%d\n",
           r_on, led_a, r_set, led_b, r_bad, r_off, g_led);
}
```

**실행 결과 (PC에서 실제 실행)**

```text
[D-2] on=0 led=1 / set=0 led=5 / zzz=-1 / off=0 led=0
```

이름과 함수를 짝지은 테이블을 만들면 `if`/`else` 사슬 대신 반복문 하나로 명령을 찾습니다. 명령을 추가할 때 테이블에 한 줄만 넣으면 됩니다. UART 콘솔의 `help`, `led on` 같은 명령 파서가 이 형태입니다.

## 콜백 등록과 드라이버 인터페이스

콜백(Callback)은 "나중에 이 일이 생기면 이 함수를 불러 달라"고 함수 포인터를 맡겨 두는 방식입니다. 인터럽트 서비스 루틴 등록이 대표적입니다.

{{svg:figures/ch05_fig01.svg|인터럽트 번호별로 핸들러와 컨텍스트를 저장하는 테이블. 등록하지 않은 번호는 NULL입니다.}}

**코드 D-3 · 콜백 등록과 컨텍스트 전달** · 파일: `src/test_func.c` · 검증: PC(gcc) 컴파일·실행 통과, 보드 미검증

```c
/* D-3. 콜백 등록과 컨텍스트 전달 (ISR 등록의 원형) */
#define IRQ_COUNT 4

typedef void (*irq_handler_t)(void *ctx);

static struct {
    irq_handler_t handler;
    void         *ctx;
} irq_table[IRQ_COUNT];

static int irq_register(unsigned irq, irq_handler_t handler, void *ctx)
{
    if (irq >= IRQ_COUNT || handler == NULL) {
        return -1;
    }
    irq_table[irq].handler = handler;
    irq_table[irq].ctx = ctx;
    return 0;
}

static void irq_dispatch(unsigned irq)   /* 실제로는 인터럽트 진입 코드가 호출한다 */
{
    if (irq < IRQ_COUNT && irq_table[irq].handler != NULL) {
        irq_table[irq].handler(irq_table[irq].ctx);
    }
}

struct tick_state {
    uint32_t count;
};

static void on_timer(void *ctx)
{
    struct tick_state *st = (struct tick_state *)ctx;
    st->count++;
}

static void demo_irq(void)
{
    struct tick_state ts = {0};
    int r0 = irq_register(0, on_timer, &ts);
    int r1 = irq_register(9, on_timer, &ts);   /* 번호가 범위 밖 */

    irq_dispatch(0);
    irq_dispatch(0);
    irq_dispatch(2);                           /* 등록하지 않은 번호 */

    printf("[D-3] register(0)=%d register(9)=%d count=%u\n",
           r0, r1, (unsigned)ts.count);
}
```

**실행 결과 (PC에서 실제 실행)**

```text
[D-3] register(0)=0 register(9)=-1 count=2
```

핸들러가 `void *ctx`를 받으면 전역 변수 없이 자기 상태를 가리킬 수 있어, 같은 핸들러 함수를 여러 장치 인스턴스가 함께 쓸 수 있습니다. 등록 함수는 번호 범위와 `NULL`을 검사하고, 호출 쪽도 등록 여부를 확인합니다.

**코드 D-4 · 함수 포인터 구조체로 만든 드라이버 인터페이스** · 파일: `src/test_func.c` · 검증: PC(gcc) 컴파일·실행 통과, 보드 미검증

```c
/* D-4. 함수 포인터 구조체로 만든 드라이버 인터페이스 */
struct uart_ops {
    void (*putc)(char c);
    int  (*getc)(void);                        /* 받은 글자가 없으면 -1 */
};

static char   log_buf[16];
static size_t log_len;

static void mem_putc(char c)
{
    if (log_len < sizeof log_buf - 1) {
        log_buf[log_len++] = c;
        log_buf[log_len] = '\0';
    }
}
static int  mem_getc(void)      { return -1; }
static void stdout_putc(char c) { putchar(c); }
static int  stdout_getc(void)   { return -1; }

static const struct uart_ops ops_mem    = { mem_putc,    mem_getc    };
static const struct uart_ops ops_stdout = { stdout_putc, stdout_getc };

static void print_str(const struct uart_ops *ops, const char *s)
{
    while (*s != '\0') {
        ops->putc(*s++);
    }
}

static void demo_ops(void)
{
    print_str(&ops_mem, "HELLO");
    printf("[D-4] ops_mem 버퍼 = \"%s\" (%zu바이트)\n", log_buf, log_len);
    printf("      ops_stdout 출력 = ");
    print_str(&ops_stdout, "HELLO");
    putchar('\n');
}
```

**실행 결과 (PC에서 실제 실행)**

```text
[D-4] ops_mem 버퍼 = "HELLO" (5바이트)
      ops_stdout 출력 = HELLO
```

`print_str()`은 UART인지 메모리인지 화면인지 모릅니다. `uart_ops`에 담긴 함수만 부릅니다. 이 분리 덕분에 보드 없이 PC에서 응용 로직을 시험할 수 있고, CPU나 칩이 바뀌어도 `ops` 구현만 교체합니다(기법 10).

### 자주 겪는 문제

| 증상 | 원인 | 조치 |
|---|---|---|
| 등록하지 않은 인터럽트에서 멈추거나 엉뚱한 곳으로 점프 | `NULL` 함수 포인터를 호출함 | 호출 전에 `NULL`을 검사하고, 테이블은 0으로 초기화합니다. |
| 핸들러가 이상한 값을 읽음 | `ctx`가 이미 끝난 함수의 지역 변수를 가리킴 | `ctx`는 전역·`static` 변수처럼 수명이 긴 객체를 가리키게 합니다. |
| 컴파일은 되는데 호출하면 오동작 | 함수 시그니처가 다른 함수를 캐스트로 억지 대입함 | 인자와 반환형을 맞추고, 캐스트로 해결하지 않습니다. |
| 함수 포인터를 `void *`에 담아 주고받음 | 표준 C는 함수 포인터와 `void *`의 변환을 보장하지 않음 | 함수 포인터 형(`typedef`)을 그대로 사용합니다. |

> **ISR 등록** 핸들러는 인터럽트 안에서 호출되므로 짧게 끝내야 합니다. ISR 작성 규칙은 기법 5에서 다룹니다.
