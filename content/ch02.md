## 메모리는 번호가 붙은 바이트의 나열

C 코드의 모든 변수는 어떤 주소에서 시작하는 연속된 바이트입니다. 임베디드 C는 이 주소를 직접 다루는 일이 대부분입니다.

| 사실 | 의미 |
|---|---|
| 메모리는 1바이트 칸의 나열이고, 칸마다 번호가 있다 | 그 번호가 주소(Address)입니다. 0부터 시작하는 정수입니다. |
| 변수는 시작 주소와 크기로 정해진다 | `uint32_t` 변수는 연속 4칸을 차지하고, 시작 주소는 4의 배수에 놓입니다(정렬). |
| 2바이트 이상 값은 바이트 순서가 있다 | 엔디안(Endianness, 바이트 순서) 규칙에 따라 낮은 바이트를 낮은 주소에 둘 수도, 높은 주소에 둘 수도 있습니다. |

{{svg:figures/ch02_fig01.svg|0x12345678을 4바이트에 저장하는 두 가지 순서. 아래 실행 결과는 위쪽(리틀 엔디안)과 같은 배열입니다.}}

**공통 머리부 · 이후 모든 예제에 포함** · 파일: 각 `src/test_*.c`의 공통 머리부

```c
#include <stdint.h>
#include <stddef.h>
#include <stdio.h>
#include <string.h>
```

**코드 A-1 · 값을 바이트 단위로 들여다보기** · 파일: `src/test_basic.c` · 검증: PC(gcc) 컴파일·실행 통과, 보드 미검증

```c
/* A-1. 값을 바이트 단위로 들여다보기 (엔디안 확인) */
static void demo_endian(void)
{
    uint32_t v = 0x12345678u;
    const uint8_t *p = (const uint8_t *)&v;   /* 같은 주소를 1바이트 단위로 읽는다 */

    printf("[A-1] v = 0x%08X\n", (unsigned)v);
    for (int i = 0; i < 4; i++) {
        printf("  바이트 %d (주소 +%d) = 0x%02X\n", i, i, (unsigned)p[i]);
    }
}
```

**실행 결과 (PC에서 실제 실행)**

```text
[A-1] v = 0x12345678
  바이트 0 (주소 +0) = 0x78
  바이트 1 (주소 +1) = 0x56
  바이트 2 (주소 +2) = 0x34
  바이트 3 (주소 +3) = 0x12
```

> **엔디안** RISC-V 기본 명세는 리틀 엔디안입니다. MicroBlaze V의 바이트 순서 설정은 AMD 공식 문서로 확인하지 못했습니다(미검증).

> **함정** `uint8_t *`로 바이트를 꺼내 읽는 코드는 엔디안에 따라 결과가 달라집니다. 시프트와 마스크로 값을 만드는 코드(기법 1)는 엔디안과 무관합니다.

## 크기, 정렬, 그리고 주소 공간

형마다 크기와 놓이는 위치의 규칙이 있고, 임베디드에서는 주변장치의 레지스터도 같은 주소 공간에 놓입니다.

### 크기와 정렬

| 형 | 크기 | 시작 주소의 규칙 |
|---|---|---|
| `uint8_t` | 1바이트 | 아무 주소나 가능 |
| `uint16_t` | 2바이트 | 2의 배수 |
| `uint32_t` | 4바이트 | 4의 배수 |
| 포인터 | 32비트 MCU는 4바이트 (64비트 PC는 8바이트) | 크기와 같은 배수 |

**코드 A-2 · 구조체의 크기와 멤버 위치** · 파일: `src/test_basic.c` · 검증: PC(gcc) 컴파일·실행 통과, 보드 미검증

```c
/* A-2. 변수 크기와 정렬 */
struct bad_order  { uint8_t a; uint32_t b; uint8_t c; };   /* 패딩이 생긴다 */
struct good_order { uint32_t b; uint8_t a; uint8_t c; };   /* 큰 것부터 */

static void demo_alignment(void)
{
    printf("[A-2] sizeof(uint8_t)=%zu sizeof(uint16_t)=%zu sizeof(uint32_t)=%zu\n",
           sizeof(uint8_t), sizeof(uint16_t), sizeof(uint32_t));
    printf("  bad_order : sizeof=%zu, offset a=%zu b=%zu c=%zu\n",
           sizeof(struct bad_order),
           offsetof(struct bad_order, a),
           offsetof(struct bad_order, b),
           offsetof(struct bad_order, c));
    printf("  good_order: sizeof=%zu, offset b=%zu a=%zu c=%zu\n",
           sizeof(struct good_order),
           offsetof(struct good_order, b),
           offsetof(struct good_order, a),
           offsetof(struct good_order, c));
}
```

**실행 결과 (PC에서 실제 실행)**

```text
[A-2] sizeof(uint8_t)=1 sizeof(uint16_t)=2 sizeof(uint32_t)=4
  bad_order : sizeof=12, offset a=0 b=4 c=8
  good_order: sizeof=8, offset b=0 a=4 c=5
```

멤버 합은 6바이트인데 `bad_order`는 12바이트입니다. `a` 뒤에 3바이트, `c` 뒤에 3바이트의 빈 칸(패딩, Padding)이 들어가 `b`를 4의 배수에 맞추고 전체 크기도 4의 배수로 맞추기 때문입니다. 큰 멤버부터 나열한 `good_order`는 8바이트입니다.

**코드 A-3 · 배열 원소의 주소 차이** · 파일: `src/test_basic.c` · 검증: PC(gcc) 컴파일·실행 통과, 보드 미검증

```c
/* A-3. 변수의 주소: 같은 배열 안에서 상대 주소만 본다 (절대 주소는 실행마다 다름) */
static void demo_addr(void)
{
    uint32_t arr[4] = {10, 20, 30, 40};
    uintptr_t base = (uintptr_t)&arr[0];

    printf("[A-3] 배열 원소 간 주소 차이\n");
    for (int i = 0; i < 4; i++) {
        printf("  &arr[%d] - &arr[0] = %zu 바이트\n", i, (size_t)((uintptr_t)&arr[i] - base));
    }
}
```

**실행 결과 (PC에서 실제 실행)**

```text
[A-3] 배열 원소 간 주소 차이
  &arr[0] - &arr[0] = 0 바이트
  &arr[1] - &arr[0] = 4 바이트
  &arr[2] - &arr[0] = 8 바이트
  &arr[3] - &arr[0] = 12 바이트
```
