## ISR은 짧게: 기록하고 알린다

**S등급** ISR(Interrupt Service Routine, 인터럽트 서비스 루틴)은 인터럽트가 발생하면 CPU가 하던 일을 멈추고 실행하는 함수입니다. ISR이 실행되는 동안 메인 코드가 멈추고 보통 다른 인터럽트도 기다리게 되므로, ISR에서는 기록하고 알리는 일만 하고 긴 처리는 메인 루프에 맡깁니다.

{{svg:figures/ch10_fig01.svg|인터럽트 처리의 흐름. ISR은 짧게 끝나고, 긴 처리는 복귀한 메인 루프가 합니다.}}

### ISR에서 하는 일과 하지 않는 일

| 구분 | 내용 | 이유 |
|---|---|---|
| 하는 일 | 상태 레지스터를 읽어 인터럽트 원인을 확인 | 어느 장치, 어느 사건인지 알아야 함 |
| 하는 일 | 인터럽트 원인을 해제 | 해제하지 않으면 ISR이 끝나자마자 다시 실행됨 |
| 하는 일 | 데이터를 읽어 버퍼에 저장, 카운터 증가, 플래그 설정 | 짧은 기록만으로 메인에 알릴 수 있음 |
| 하지 않는 일 | `printf` 같은 느린 출력, 긴 반복과 계산 | ISR이 길어지면 메인과 다른 인터럽트가 늦어짐 |
| 하지 않는 일 | 타임아웃 없는 대기, 다른 장치 폴링 | ISR이 끝나지 않으면 시스템 전체가 멈춤 |
| 하지 않는 일 | `malloc`, `free`, 재진입에 안전하지 않은 라이브러리 호출 | 실행 시간이 일정하지 않고, 끊긴 메인 코드와 내부 상태가 엉킬 수 있음 |

**코드 5-1 · 플래그와 카운터: 메인이 바쁜 사이 인터럽트가 겹쳤을 때** · 파일: `src/test_isr.c` · 검증: PC(gcc) 컴파일·실행 통과, 보드 미검증

```c
/* 5-1. 플래그와 카운터: 메인이 바쁜 사이 인터럽트가 겹쳤을 때 */
static volatile uint8_t  ev_flag;        /* ISR가 1로 올리고, 메인이 0으로 내린다 */
static volatile uint32_t ev_count;       /* ISR만 쓴다 (메인은 읽기만 한다) */
static uint32_t          ev_seen;        /* 메인만 쓴다 */

static void event_isr(void)              /* 인터럽트가 발생하면 호출되는 함수 */
{
    ev_count++;                          /* 발생 횟수를 센다 */
    ev_flag = 1u;                        /* 메인에 알린다 */
}

static uint32_t take_by_flag(void)       /* 플래그 방식: 몇 번 발생했든 한 번으로 보인다 */
{
    if (ev_flag != 0u) {
        ev_flag = 0u;
        return 1u;
    }
    return 0u;
}

static uint32_t take_by_count(void)      /* 카운터 방식: 발생한 횟수만큼 처리한다 */
{
    uint32_t now = ev_count;             /* 한 번만 읽어 변수에 담는다 */
    uint32_t n = now - ev_seen;          /* 부호 없는 뺄셈이라 카운터가 되감겨도 맞다 */

    ev_seen = now;
    return n;
}

static void demo_merge(void)
{
    event_isr();                         /* 메인이 바쁜 사이 인터럽트가 3번 발생 */
    event_isr();
    event_isr();
    printf("[5-1] 3번 발생 후 메인이 확인: 플래그 방식=%u회, 카운터 방식=%u회\n",
           (unsigned)take_by_flag(), (unsigned)take_by_count());

    ev_count = 0xFFFFFFFEu;              /* 카운터가 되감기기 직전으로 만든다 */
    ev_seen  = 0xFFFFFFFEu;
    event_isr();
    event_isr();
    event_isr();
    printf("      카운터가 0xFFFFFFFE에서 시작해 되감겨도: %u회\n",
           (unsigned)take_by_count());
}
```

**실행 결과 (PC에서 실제 실행)**

```text
[5-1] 3번 발생 후 메인이 확인: 플래그 방식=1회, 카운터 방식=3회
      카운터가 0xFFFFFFFE에서 시작해 되감겨도: 3회
```

플래그는 인터럽트가 몇 번 발생했든 "발생했다"는 사실 하나만 전달합니다. 횟수가 중요하면 ISR이 카운터를 올리고, 메인이 이전에 본 값과의 차이를 구합니다. 부호 없는 뺄셈이라 카운터가 되감겨도 맞습니다(기법 3).

변수마다 쓰는 쪽을 하나로 정하면 읽기-수정-쓰기 경합이 생기지 않습니다. `ev_count`는 ISR만, `ev_seen`은 메인만 씁니다. 32비트 CPU(RISC-V, ARM)에서는 정렬된 32비트 변수를 한 번의 읽기로 읽으므로, 메인은 `ev_count`를 한 번만 읽어 변수에 담으면 됩니다. 8비트·16비트 CPU에서는 읽는 도중에 값이 바뀔 수 있습니다(기법 11).

## 공유 변수와 인터럽트 원인 해제

ISR과 메인이 함께 쓰는 변수에는 `volatile`을 붙이고, ISR은 가장 먼저 인터럽트 원인을 지웁니다. 둘 중 하나를 빼먹으면 최적화한 빌드에서만, 또는 드물게 문제가 나타납니다.

**코드 5-2 · ISR과 공유하는 플래그 (PC의 시그널 핸들러가 ISR 역할)** · 파일: `src/vol_signal.c` · 검증: PC(gcc) 컴파일·실행 통과, 보드 미검증

```c
/* 5-2. ISR(시그널 핸들러)과 공유하는 플래그 */
#ifdef USE_VOLATILE
static volatile sig_atomic_t done;        /* volatile 있음 */
#else
static sig_atomic_t done;                 /* volatile 없음 */
#endif

static void on_alarm(int sig)             /* ISR 역할: 플래그만 올린다 */
{
    (void)sig;
    done = 1;
}

int main(void)
{
    signal(SIGALRM, on_alarm);
    alarm(1);                             /* 1초 뒤에 "인터럽트"가 발생한다 */

    while (!done) {
        /* 메인 루프: 인터럽트를 기다리며 다른 일을 하는 중 */
    }
    printf("루프 종료\n");
    return 0;
}
```

1초 뒤에 핸들러가 플래그를 올리는 프로그램을 빌드 설정을 바꿔 실행했습니다. gcc 13.3.0, 3초가 지나도 끝나지 않으면 강제로 종료했습니다.

| 빌드 | 결과 |
|---|---|
| `-O2` (volatile 없음) | 3초가 지나도 끝나지 않아 강제 종료 |
| `-O2 -DUSE_VOLATILE` (volatile 있음) | 약 1.0초 뒤 `루프 종료` 출력 |
| `-O0` (volatile 없음) | 약 1.0초 뒤 `루프 종료` 출력 |

volatile이 없으면 컴파일러가 플래그를 루프 밖에서 한 번만 읽습니다(기법 2). 최적화를 끄면 같은 코드가 정상 동작해서 문제가 숨습니다. 디버그 빌드에서는 되고 최적화 빌드에서만 멈추는 증상이 이 경우입니다.

**코드 5-3 · 인터럽트 원인을 지우지 않는 ISR (가상 인터럽트 컨트롤러)** · 파일: `src/test_isr.c` · 검증: PC(gcc) 컴파일·실행 통과, 보드 미검증

```c
/* 5-3. 인터럽트 원인을 지우지 않는 ISR (가상 인터럽트 컨트롤러) */
static int irq_pending;                  /* 장치가 올린 인터럽트 요청. 지우기 전까지 유지된다 */
static int isr_calls;

static void irq_clear(void)
{
    irq_pending = 0;
}

static void isr_without_clear(void)      /* 원인을 지우지 않는다 */
{
    isr_calls++;
}

static void isr_with_clear(void)         /* 원인을 가장 먼저 지운다 */
{
    irq_clear();
    isr_calls++;
}

static int run_irq(void (*isr)(void))    /* 요청이 남아 있으면 CPU가 곧바로 ISR에 다시 들어간다 */
{
    int guard = 0;

    isr_calls = 0;
    irq_pending = 1;
    while (irq_pending && guard < 5) {   /* 실제로는 guard 없이 끝없이 반복한다 */
        isr();
        guard++;
    }
    return isr_calls;
}

static void demo_clear(void)
{
    printf("[5-3] 원인을 지우지 않는 ISR: %d회 호출 후 중단 (실제로는 끝없이 반복)\n",
           run_irq(isr_without_clear));
    printf("      원인을 지우는 ISR: %d회 호출\n", run_irq(isr_with_clear));
}
```

**실행 결과 (PC에서 실제 실행)**

```text
[5-3] 원인을 지우지 않는 ISR: 5회 호출 후 중단 (실제로는 끝없이 반복)
      원인을 지우는 ISR: 1회 호출
```

인터럽트 요청이 남아 있으면 ISR이 끝나자마자 CPU가 다시 ISR로 들어갑니다. 원인을 지우지 않는 ISR은 끝없이 반복하고, 메인 루프는 실행되지 못합니다. 원인 해제는 ISR 첫머리에서 합니다. 해제 방법은 장치마다 다르며(상태 비트에 1을 써서 지우기, 데이터 레지스터를 읽으면 지워지기 등) 데이터시트로 확인합니다(기법 2).

### 작성 규칙

| 규칙 | 이유 |
|---|---|
| ISR은 원인 확인, 원인 해제, 기록, 알림만 한다 | 실행 시간을 짧게 유지 |
| 가장 먼저 인터럽트 원인을 지운다 | 지우지 않으면 ISR이 끝나자마자 다시 실행됨 |
| ISR과 메인이 함께 쓰는 변수는 `volatile` | 메인 루프의 읽기가 최적화로 사라지지 않음(기법 2) |
| 변수마다 쓰는 쪽을 하나로 정한다 | 읽기-수정-쓰기 경합이 생기지 않음 |
| 이벤트 횟수가 중요하면 플래그 대신 카운터나 링 버퍼 | 플래그는 겹친 이벤트를 하나로 합침(기법 7) |
| 긴 처리는 메인 루프에서 한다 | ISR 시간이 길어지면 다른 인터럽트와 메인이 늦어짐 |

### 자주 겪는 문제

| 증상 | 원인 | 조치 |
|---|---|---|
| 최적화한 빌드에서만 메인 루프가 플래그를 영원히 못 봄 | 공유 플래그에 `volatile`이 빠짐 | 코드 5-2처럼 `volatile`을 붙입니다. |
| 인터럽트가 한 번 발생했는데 ISR만 계속 실행되고 메인이 멈춤 | 인터럽트 원인을 지우지 않음 | ISR 첫머리에서 원인을 지웁니다(코드 5-3). |
| 입력 이벤트가 가끔 빠짐 | 플래그가 여러 이벤트를 하나로 합침 | 카운터나 링 버퍼를 씁니다. |
| 수신 데이터가 깨지거나 빠짐 | ISR이 길어져 다음 데이터를 놓침 | ISR은 버퍼에 저장만 하고 처리는 메인에서 합니다. |
| 8비트·16비트 CPU에서 값이 가끔 깨짐 | 메인이 여러 바이트를 읽는 도중 ISR이 값을 바꿈 | 기법 11 |
| ISR 안에서 `printf`를 호출한 뒤 동작이 불안정 | 느리고 재진입에 안전하지 않음 | ISR은 플래그만 올리고, 출력은 메인에서 합니다. |

> **ISR 등록** ISR을 등록하는 방식은 기초 D의 콜백 등록과 같은 원리입니다. 인터럽트 진입 처리는 CPU마다 다르므로 CPU 종속 파일에 격리합니다(기법 10).
